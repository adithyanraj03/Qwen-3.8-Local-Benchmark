Typer Architecture

Typer is a thin, high-level layer over Click — more precisely, over a vendored, pruned copy of Click 8.3.1 kept in typer/_click/. Its core job is a compiler: it turns Python function signatures (type hints, defaults, Annotated metadata) into Click Command/Parameter objects, then lets the Click engine do the actual parsing. All line references are to the tree as of this commit.

Main modules and how they depend on each other

Layer 0 — primitives (no Typer-internal deps)

Module Role
typer/exceptions.py TyperException, Abort, Exit (the exit-code carrier).
typer/_typing.py Small typing toolkit: get_args/get_origin, is_union, is_literal_type (pydantic-1.x heritage, typer/_typing.py:1).
typer/colors.py Re-export of vendored Click's color names.

Layer 1 — the vendored engine typer/_click/

A reduced Click: no decorators API for end users, no Group (Typer supplies its own), fewer extras. Key pieces:

  • typer/_click/core.py — Context (:118), Command with make_context (:687), parse_args (:711), invoke (:729), and Parameter with the per-value pipeline handle_parse_result → consume_value → process_value → type_cast_value (:1051, :920, :988, :940), plus eager-first ordering (iter_params_for_processing, :74).
  • typer/_click/parser.py — _OptionParser (:207), the getopt-style tokenizer that splits argv into (opts, args, invocation_order).
  • typer/_click/types.py — the ParamType hierarchy (STRING, INT, BOOL, File, ranges, convert_type).
  • typer/_click/{shell_completion,termui,formatting,globals,utils,exceptions}.py — completion protocol, prompts, help formatter, context stack, errors.

The fork is coupled, not pure: typer/_click/core.py:19 imports Abort/Exit from typer.exceptions (an upward dependency, worth knowing about).

Layer 2 — internal data model: typer/models.py

Plain state holders with no behavior: Required = ... marker (:28), DefaultPlaceholder/Default (:170, :190), CommandInfo (:200), VersionInfo (:235), TyperInfo (:250), the param-info family ParameterInfo/OptionInfo/ArgumentInfo (:295, :403, :531), ParamMeta (:635), marker types (Context, FileText*, FileBinary*, CallbackParam, :31–167), and the one behavior class, the TyperPath param type (:663).

Layer 3 — public API and the compiler

  • typer/params.py — Option() / Argument() are factories that build OptionInfo/ArgumentInfo (params.py:948, :1785), with huge fully Annotated
  • Doc() signatures purely for IDE tooltips. No parsing logic.
  • typer/main.py — the heart. The Typer class (:148) is a registration facade: command() (:783) and callback() (:579) and add_typer() (:945) merely append CommandInfo/TyperInfo to registered_commands / registered_callback / registered_groups (:574–577); add_version_option() (:1163) stores a VersionInfo. Everything compile-side lives in this module too: get_command (:1284), get_group_from_info (:1403), get_command_from_info (:1512), get_params_convertors_ctx_param_name_from_function (:1493), get_click_param (:1752), get_click_type (:1650), get_callback (:1616), the pretty-exception hook (:62), plus run()/launch().
  • typer/utils.py — get_params_from_function (:107): inspects a signature (eval_str=True, plus get_type_hints for forward refs), splits Annotated[type, OptionInfo()] from real annotations (:94), enforces the "don't mix Annotated-style and default-style" rules, and normalizes both into ParamMeta(name, default, annotation). This is what makes name: str, name: Annotated[str, Option(...)] and name = Option(...) converge into one path.

Layer 4 — Click subclasses: typer/core.py

Where Typer bends Click to its semantics:

  • TyperArgument (:245) / TyperOption (:435): Typer-flavored parameters — flag machinery incl. --x/--no-x secondary opts (add_to_parser :588), auto-envvar reads (resolve_envvar_value :686), prompt-on-missing (consume_value :705), help-record duplication for defaults display (get_help_record :752, with helpers _get_default_string :85, _extract_default_help_str :140 extracted precisely so rich_utils can reuse them).
  • TyperCommand (:903) / TyperGroup (:991): wire in rich help and completion short-circuits (main → _main :158, format_help :975/:1208); TyperGroup even re-implements the Click Group dispatch Typer removed from the fork (invoke :1088, resolve_command :1171 — which adds the difflib "Did you mean…" suggestions), and preserves command definition order (list_commands :1219).
  • HAS_RICH / MarkupMode (:24–32) decide rich-vs-plain everywhere.

Layer 5 — presentation, extras, entry points

  • typer/rich_utils.py — all rich imports live here (enforced by ruff TID251/TID253; other modules import it lazily inside functions, e.g. typer/core.py:206, :982). rich_format_help (:555), rich_format_error (:697), get_traceback (:761).
  • typer/completion.py + _completion_classes.py + _completion_shared.py — --install-completion/--show-completion options built from a placeholder function (completion.py:64–97) so they flow through the same get_click_param pipeline as user params; shell classes and script templates.
  • typer/testing.py — CliRunner (:128): stream isolation + invoke (:275), the same standalone main() path tests exercise.
  • typer/cli.py + typer/__main__.py — Typer's own CLI (python -m typer): a TyperCLIGroup (cli.py:54) that dynamically materializes another Typer app's commands as subcommands.
  • typer/__init__.py — public facade (version at __init__.py:3).

Dependency direction: __init__ → main → {completion, core, models, utils}; core → _click + exceptions + utils (+ lazy rich_utils, completion); models → _click; params → models; utils → models; rich_utils → core, models; testing → main. The single upward edge is _click → typer.exceptions.

Request flow: from decorated function to parsed command line

Phase A — registration (import time; nothing is parsed). @app.command() just stores the raw function in a CommandInfo (main.py:920–940); typer.Option(...) in a signature is likewise just an OptionInfo object. Sub-apps registered with add_typer are stored as TyperInfo (main.py:1138). No Click objects exist yet.

Phase B — materialization (first app() call). 1. Typer.__call__ (main.py:1244) installs the pretty-exception hook and calls get_command(self)(*args). 2. get_command (main.py:1284) chooses shape: a TyperGroup (if a callback, any sub-group, or ≥2 commands — built recursively by get_group_from_info :1403) or a single TyperCommand (get_command_from_info :1512). App-level settings are resolved through a three-level precedence (explicit at add_typer > sub-app @callback() > Typer() > built-in) using DefaultPlaceholder detection (solve_typer_info_defaults :1368, help at solve_typer_info_help :1331). Auto-added options (--install-completion, --show-completion, --version) are appended here (:1301–1304, :1321–1324). 3. For each command callback, get_command_from_info derives the command name (get_command_name :1480: lower().replace("_", "-")) and help (docstring), then get_params_convertors_ctx_param_name_from_function (:1493) per parameter: - get_params_from_function (utils.py:107) → ParamMetas (annotation, default or OptionInfo/ArgumentInfo, Required markers normalized). - _click.Context-annotated params are pulled aside as context_param_name. - get_click_param (:1752) classifies: Required/no-default → Argument, plain default → Option, explicit *Info → as declared; unwraps T | None/Optional, maps list[T] → multiple=True (nargs=-1 for arguments), tuple[...] → composite type; get_click_type (:1650) maps the Python type to a Click ParamType (Path→TyperPath, Enum/Literal→ TyperChoice, file markers→File, bounded int→IntRange, …; parser=/ click_type= escape hatches win first, :1533–1537). - Values Click can't produce natively (Path, enum members, lists/tuples) get a post-parse convertor (determine_type_convertor :1557), either wrapped into the param's callback (get_param_callback :1917) or applied to the wrapper's kwargs. - get_callback (:1616) wraps the user function in a kwargs-only wrapper that applies convertors and injects get_current_context() — the user function never sees a Click object unless it asks. 4. Execution (TyperCommand.main/TyperGroup.main → _main, core.py:158): argv (expanded on Windows), shell-completion env-var short-circuit (:182), then vendored Command.make_context (_click/core.py:687) → parse_args (:711): _OptionParser.parse_args tokenizes argv; then for every parameter in eager-first / invocation order (_click/core.py:74), handle_parse_result (:1051) runs consume_value (commandline → envvar (incl. auto-prefix, typer/core.py:686) → default_map → default; Typer adds interactive prompt fallback at typer/core.py:705) → process_value → type_cast_value (raises BadParameter on bad input) → required-check → param callback. Results land in ctx.params. 5. Groups: TyperGroup.invoke (typer/core.py:1088) resolves the subcommand (resolve_command :1171, with suggestions), runs the group callback, then recurses into sub_ctx.command.invoke(sub_ctx). 6. Leaf: _click/core.py:729 ctx.invoke(self.callback, **ctx.params) → the get_callback wrapper → convertors → the user function, with real Python values. 7. Errors: UsageError/ClickException → rich_utils.rich_format_error or e.show() (core.py:203–212); typer.Exit/Abort handled in _main (:220–242); uncaught user exceptions propagate to except_hook (main.py:61–109), which strips Typer/Click frames and renders a Rich traceback or a trimmed stdlib one.

Design decisions

Good ones

  1. Deferred compilation with plain data registries. Decorators store inert CommandInfo/TyperInfo/OptionInfo objects; the whole Click tree is built only in get_command() at invocation (main.py:1284). This is why registration order doesn't matter, add_typer can be mutated before first call, the DefaultPlaceholder precedence rules (main.py:1368) are possible, and external tooling (Typer's own cli.py doc-dump) can introspect or rebuild apps. The --install-completion trick of building options from a fake command function (completion.py:64) so they ride the exact same pipeline as user params is a particularly nice consequence.
  2. Fork-and-subclass Click instead of patching it. Vendoring a trimmed Click 8.3.1 (typer/_click/) plus explicit subclasses (TyperOption, TyperArgument, TyperCommand, TyperGroup) means no monkey-patching and no breakage from upstream releases; overrides are self-documenting with "Typer override" comments (e.g. core.py:114–125, :752–755), and Typer can delete what it replaces (Click's Group, re-implemented at typer/core.py:991).
  3. DefaultPlaceholder/Default for "was it actually set?". Sentinels (models.py:170–197) let Typer distinguish an explicit help=None from "not specified", enabling the multi-level inheritance of app settings (add_typer(...) > @sub.callback() > Typer(...)) in solve_typer_info_defaults (main.py:1368) — with plain None defaults this precedence would be impossible.

Ones I would change

  1. Kwarg-signature explosion. The same ~25 settings are re-declared verbatim in Typer.__init__ (main.py:165–577), Typer.callback (:579), Typer.add_typer (:945), and TyperInfo (models.py:250); the same 40+ param infos appear again in ParameterInfo/OptionInfo/ArgumentInfo (models.py:295–634) and in Option/Argument overloads in params.py (1,833 lines total). Adding one option means touching 5–6 places, and drift already shows (e.g. deprecated's default/behavior is re-passed by hand everywhere). I'd define each parameter spec once (dataclass-driven, or a shared **kwargs core with generated @overloads) so signatures can't diverge.
  2. Blurred fork boundary of _click. The vendored Click is supposed to be a private engine, yet typer/_click/core.py:19 imports from typer.exceptions, and Typer reaches into vendored internals in many places (private ctx._protected_args/param._custom_shell_complete, the copied _split_opt at typer/core.py:36, the re-implemented _main_shell_completion seam at typer/core.py:882). It's neither a drop-in library nor a clean fork, which makes re-syncing with upstream Click error-prone. I'd formalize the seam — an adapter/module that owns all overrides and Typer-side hooks, keeping the vendored files byte-diffable against upstream Click.
