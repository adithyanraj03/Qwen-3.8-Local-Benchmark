Architecture

Typer 0.27.3 (typer/__init__.py:3) with a vendored fork of Click 8.3.1 in typer/_click/ (typer/_click/__init__.py:1-3). The package has two halves:

  • Typer's own layer (typer/*.py): a declarative, type-hint-driven API that registers commands and parameters as plain Python objects.
  • The Click runtime (typer/_click/*.py): contexts, the option parser, parameter value processing, help formatting primitives, and terminal UI.

Typer never exposes Click objects to user code directly; it builds them lazily from its own registration data right before execution.

Request flow: from a decorated function to a parsed command line

Phase 1: registration (import time, no Click objects)

  1. @app.command() (main.py:753) appends a CommandInfo holding the raw function to app.registered_commands and returns the function unchanged (main.py:890-911), so the module stays importable and the function stays directly callable. @app.callback() and app.add_typer() work the same way via TyperInfo (main.py:728-751, main.py:1108-1131).
  2. Parameter declarations are also inert: typer.Option(...)/typer.Argument(...) just build OptionInfo/ArgumentInfo objects, either as default values or inside Annotated[...].

Phase 2: build the Click tree (first call)

  1. app() (main.py:1133-1154) installs the custom sys.excepthook (main.py:1134-1135) and calls get_command(self) (main.py:1173).
  2. get_command decides the shape: a TyperGroup if there is a callback, any sub-group, or more than one command; otherwise a single TyperCommand (main.py:1176-1205). Completion options are appended here (main.py:1174-1175, main.py:1184-1186).
  3. get_command_from_info (main.py:1392) derives the command name from the function name (main.py:1360-1361), the help from the docstring (main.py:1400-1404), and converts every function parameter: - get_params_from_function (utils.py:107) reads the signature, peels Typer annotations out of Annotated (utils.py:94-104), normalizes the two declaration styles into a single ParameterInfo carried as the default (utils.py:119-181), and yields ParamMeta(name, default, annotation). - get_click_param (main.py:1632) decides Argument vs Option from the presence of a default (main.py:1641-1652), unwraps Optional/list/tuple (main.py:1665-1693), maps the Python annotation to a Click ParamType via get_click_type (main.py:1530: int->INT/IntRange, Enum/Literal-> TyperChoice (_types.py:12), Path->TyperPath (models.py:648), FileText*->File, etc.), and auto-generates flag names such as --my-flag/--no-my-flag for bools (main.py:1706-1719). - Python-level conversions Click cannot express (Path, Enum members, list/tuple element conversion) become converter functions (main.py:1437-1493) attached to the user callback wrapper or to the parameter callback (main.py:1797-1846). - get_callback (main.py:1496) wraps the user function in a wrapper that applies converters, injects the current Context if the function declares one (main.py:1522-1523), and calls the function with keyword arguments.
  4. The result is a tree of TyperCommand/TyperGroup objects whose params are TyperArgument/TyperOption instances.

Phase 3: parse and invoke (per run)

  1. TyperCommand.main/TyperGroup.main call the adapted _main (core.py:158): reads sys.argv (with Windows glob expansion, core.py:173-174), handles shell-completion env-var requests and exits early (core.py:182, core.py:882-900), then make_context + invoke (core.py:186-187).
  2. make_context (_click/core.py:687-709) creates a Context (_click/core.py:118) and runs parse_args inside a cleanup scope.
  3. Command.parse_args (_click/core.py:711-727): - make_parser (_click/core.py:611-616) asks each parameter to register itself: TyperOption.add_to_parser (core.py:588-625) maps flags to store_const/append_const actions (including secondary --no-* opts), TyperArgument.add_to_parser (core.py:431-432) registers positionals. - _OptionParser.parse_args (_click/parser.py:275) does the raw token scan and returns (opts, args, invocation_order). - Parameters are then processed in iter_params_for_processing order (eager first, then invocation order; _click/core.py:74-98) via handle_parse_result (_click/core.py:1051-1079), which for each parameter: consume_value (command line -> env var incl. Typer's auto-envvar (core.py:686-703) -> default_map -> default, with interactive prompting for options that ask for it (core.py:705-728)), type_cast_value through the ParamType (_click/core.py:940-982), required-check and user callback in process_value (_click/core.py:988-998), and finally stores the result in ctx.params.
  4. For a group, TyperGroup.invoke (core.py:1088-1119) runs the group callback, resolves the subcommand (resolve_command, core.py:1171, which adds "Did you mean ...?" suggestions via difflib when enabled), and recurses into the subcommand's own make_context/invoke.
  5. Command.invoke (_click/core.py:729-741) calls ctx.invoke(self.callback, **ctx.params) -> Typer's wrapper from step 5 -> the user's function, now with real Python values (Path, enum members, open files, typed scalars).
  6. Failure paths: UsageError/ClickException are rendered as Rich error panels or plain text and exit with the error code (core.py:203-212, rich_utils.py:697); typer.Exit/typer.Abort are translated to exit codes in _main (core.py:220-242); unexpected exceptions reach the except_hook installed in step 3, which strips Typer/Click frames (main.py:61-109).

Design decisions

Good ones

  1. Two-phase architecture: inert registration, lazy Click construction. Decorators only append plain info objects and return the original function (main.py:890-911); the Click tree is built on demand in get_command (main.py:1173). This keeps decorated modules importable and testable as plain libraries, keeps import time free of Click work, lets CliRunner rebuild a pristine tree per invocation (testing.py:285), and makes the whole app introspectable before any parsing happens. It also lets cli.py mount an arbitrary user app as a subcommand simply by calling typer.main.get_command (cli.py:85-92).

  2. The DefaultPlaceholder sentinel for three-level default resolution. Default(value) wraps defaults in a DefaultPlaceholder (models.py:170-197) so the code can distinguish "user explicitly passed False/None" from "user never passed anything". solve_typer_info_defaults (main.py:1248-1280) then resolves each setting with a clear precedence: add_typer(...) > @sub_app.callback(...) > Typer(...) constructor > built-in default, with a parallel six-step chain just for help text (main.py:1211-1245). Without the sentinel, no_args_is_help=False at one level could never override True at another.

  3. Vendoring Click and unifying the exception vocabulary. Click 8.3.1 lives inside the package (_click/__init__.py:1-3), and the vendored core imports Typer's own Exit/Abort (_click/core.py:19). That let Typer restructure the parts it needs most (a TyperGroup that owns its own dispatch instead of click.Group, core.py:991; a help option built from TyperOption and cached, _click/core.py:590-609; Typer-flavored parser actions) without waiting on upstream or fighting version drift, and guarantees one exception type flows coherently through both layers.

Ones I would change

  1. The sixfold duplication of the parameter surface. The same ~20 command settings are re-declared in Typer.__init__ (main.py:135-519), Typer.callback (main.py:549-700), Typer.add_typer (main.py:915-1086), TyperInfo (models.py:235-277), and CommandInfo (models.py:200-232); the ~40 parameter settings are re-declared in ParameterInfo, OptionInfo, ArgumentInfo (models.py:280-617), the Option/Argument overloads (params.py), and again in TyperOption/TyperArgument (core.py:248-298, core.py:440-477). Every new feature (e.g. rich_help_panel) has to be threaded through all of them, which is the single biggest tax on contributing here. I would collapse the info classes onto dataclasses and have the public signatures delegate through **kwargs-style forwarding (or generate the Doc-annotated overloads), keeping only the genuinely public parameters explicit.

  2. Copy-paste overrides instead of hooks in the vendored Click. Because Click is now internal, behavior changes could be small protected hooks, but several places instead fork whole functions that will silently drift from their source: _main is a full copy of Click's main() (core.py:158-242, "Originally copied from _click.main()"), TyperOption.get_help_record duplicates all of Click's logic to change one line (core.py:752-845, the comment at core.py:753-755 says exactly that), and the default-string helpers were "Extracted from _click.core.Option.get_help_record()" (core.py:85-137). Related latent hazard: get_callback builds one shared use_params dict per wrapper and mutates it on every invocation (main.py:1507-1524), so state persists across repeated calls of the same command object; a per-call dict would be safer. (Smaller sibling of the same problem: chain is accepted through the whole public API (main.py:217-229) but TyperGroup never implements it - the handling is commented out at core.py:1101 - so it should be removed or finished.)
