Typer Architecture

Typer (v0.27.3, typer/__init__.py:3) is a CLI library built on top of Click. A defining feature of this codebase is that Click is vendored into typer/_click/ ("Code taken and adapted from Click ... 8.3.1", typer/_click/__init__.py:1-3) and then modified in place, rather than being an external dependency.

Main modules and their dependencies

                      +-------------+
   user code  ------> | main.py     |  Typer class, decorator -> Click translation
                      +-------------+
                        |  uses     \  builds
                        v            v
   +-----------+   +-----------+  +--------------+
   | models.py |<--| core.py   |  | utils.py     |  signature/Annotated inspection
   +-----------+   +-----------+  +--------------+
        |              |  \
        |              |   \----> rich_utils.py (lazy, only if Rich installed)
        v              v
   +---------------------------------+
   | _click/  (vendored Click 8.3.1) |
   +---------------------------------+
        ^
        |  also imports typer.exceptions  (bidirectional!)
  • typer/__init__.py — public API surface. Re-exports Typer, Argument, Option, Exit, Abort, echo, prompt, etc., mostly from main, params, models and _click (typer/__init__.py:7-33).
  • typer/main.py — the heart of the library. The Typer class (main.py:119) with command() (main.py:753), callback() (main.py:549), add_typer() (main.py:915) and __call__() (main.py:1133); plus the whole "Typer → Click" compiler: get_command() (main.py:1173), get_group_from_info() (main.py:1283), get_command_from_info() (main.py:1392), get_click_param() (main.py:1632), get_click_type() (main.py:1530), get_callback() (main.py:1496). Also run() (main.py:1902) and the pretty traceback except_hook (main.py:61). Depends on core, models, utils, completion, _click, _types, _typing.
  • typer/models.py — pure data holders, no logic: CommandInfo (models.py:200), TyperInfo (models.py:235), ParameterInfo/OptionInfo/ArgumentInfo (models.py:280, :388, :516), ParamMeta (models.py:620), the Default/DefaultPlaceholder sentinel (models.py:170-197), file-like marker classes (models.py:41-158) and TyperPath, a Typer-flavored path ParamType (models.py:648). Depends only on _click.
  • typer/params.py — user-facing Option() and Argument() functions. They are thin factories that just return OptionInfo/ArgumentInfo (params.py:948, params.py:1785); most of the file's 1833 lines are Annotated[..., Doc(...)] parameter documentation. Depends on models.
  • typer/utils.py — get_params_from_function() (utils.py:107): reads a function's signature (inspect.signature(..., eval_str=True), utils.py:108), splits Annotated[T, typer.Option(...)] annotations from the real type (utils.py:94-104), validates that Annotated-style and default-style declarations are not mixed (utils.py:119-181) and produces ParamMeta records.
  • typer/core.py — Typer's subclasses of the vendored Click classes: TyperArgument (core.py:245, makes arguments show their name in help), TyperOption (core.py:435, flag/prompt/envvar behavior), TyperCommand (core.py:903) and TyperGroup (core.py:991, incl. "did you mean" suggestions in resolve_command, core.py:1171-1186). Also _main() (core.py:158), a re-implementation of Click.main() that adds Rich error formatting and Typer's Exit/Abort handling, and the HAS_RICH feature flag (core.py:27). Depends on _click, exceptions, utils, and lazily on rich_utils/completion.
  • typer/_click/ — vendored Click: core.py (Context :118, Command :503, Parameter :805), parser.py (_OptionParser :207), types.py (ParamType hierarchy :30, convert_type :622), shell_completion.py, termui.py, utils.py, exceptions.py, etc.
  • typer/rich_utils.py — Rich-based help rendering (panels for options/commands: :355, :479; rich_format_help :555), error formatting (rich_format_error :697) and pretty tracebacks (get_traceback :761). Imported lazily everywhere so Rich stays optional.
  • typer/completion.py + _completion_classes.py + _completion_shared.py — the --install-completion/--show-completion options are declared as a fake function (completion.py:64-97) whose params are extracted with the normal machinery and appended to the top-level command (main.py:1174-1175, :1184-1186); shell-specific completion scripts live in _completion_classes.py.
  • typer/cli.py — the python -m typer developer tool (__main__.py:1-3): dynamically imports a file/module, finds a Typer app or function (cli.py:72-117), mounts it as a run subcommand (cli.py:140-150), and can generate Markdown docs (cli.py:279).
  • typer/testing.py — a Click-style CliRunner (testing.py:128) that calls typer.main.get_command(app) and cli.main(...) with captured streams (testing.py:275-342).
  • typer/exceptions.py — TyperException, Abort, Exit (exceptions.py:1-29).
  • typer/_typing.py / typer/_types.py — typing helpers (union/literal detection) and TyperChoice, the enum/Literal ParamType (_types.py:12).

Dependency direction is mostly main → core → _click, main/params → models, main → utils → models. Two notable exceptions:

  1. The vendored _click depends back on Typer: _click/core.py:19 does from ..exceptions import Abort, Exit, and _complete_visible_commands (_click/core.py:36-53) and Command.shell_complete (_click/core.py:757) import TyperGroup/TyperOption from typer.core at runtime. The cycle is kept alive by function-level imports.
  2. rich_utils imports from core and models, but core imports rich_utils lazily inside methods (core.py:982, core.py:207).

Request flow: from a decorated function to a parsed command line

Registration time (no Click objects yet). @app.command() only appends a CommandInfo holding the raw function to app.registered_commands (main.py:890-911); @app.callback() stores a TyperInfo (main.py:728-749); app.add_typer() stores a TyperInfo wrapping the sub-app (main.py:1108-1131).

Call time. app() (main.py:1133-1154) installs the pretty-exception hook and calls get_command(self)(*args):

  1. Choose shape — get_command() (main.py:1173-1208): a callback, groups, or >1 command means a TyperGroup; exactly one command means a bare TyperCommand. Completion options are appended here.
  2. Resolve defaults — solve_typer_info_defaults() (main.py:1248-1280) merges settings with three-way precedence (add_typer arg > sub-app @callback() > Typer() arg), using DefaultPlaceholder to tell "unset" from "explicitly None".
  3. Introspect the function — get_params_convertors_ctx_param_name_from_function() (main.py:1373-1389) calls get_params_from_function() (utils.py:107) to get ParamMeta(name, default, annotation) records; a typer.Context-annotated param is pulled out as context_param_name instead of becoming a CLI param.
  4. Map to Click params — get_click_param() (main.py:1632-1794) decides Argument-vs-Option from the default (.../no default → required Argument; a value → Option; explicit OptionInfo/ArgumentInfo wins), unwraps Optional/list/tuple (main.py:1665-1693), and get_click_type() (main.py:1530-1625) maps the annotation to a ParamType (int+min/max → IntRange, Enum/Literal → TyperChoice, Path → TyperPath, FileText → File, ...). bool options become flags with --name/--no-name (main.py:1706-1719).
  5. Wrap the callback — get_callback() (main.py:1496-1527) returns a Click-shaped wrapper that applies post-parse convertors (Path, enum members, list/tuple fixups), injects the current Context, and calls the user function with keyword args.

Execution time (TyperCommand.main → _main, core.py:955/core.py:158):

  1. _main first handles shell completion via the _*_COMPLETE env var (_typer_main_shell_completion, core.py:882-900), then make_context() (_click/core.py:687-709) → parse_args() (_click/core.py:711-727).
  2. make_parser (_click/core.py:611-616) asks each param to add_to_parser (TyperOption.add_to_parser, core.py:588-625); _OptionParser.parse_args (_click/parser.py:275-291) tokenizes argv into (opts, leftover args, invocation order).
  3. For each param, in invocation-then-eagerness order (iter_params_for_processing, _click/core.py:74-98), handle_parse_result (_click/core.py:1051-1079) runs consume_value (CLI → envvar → default_map → default, _click/core.py:920-938), process_value (type conversion via ParamType.convert, required check, param-level callback, _click/core.py:988-998) and stores the result in ctx.params.
  4. invoke (_click/core.py:729-741) calls the wrapped user callback with **ctx.params; for groups, TyperGroup.invoke (core.py:1088-1119) resolves the subcommand (resolve_command, core.py:1171, with typo suggestions), invokes the group callback, then recurses into the subcommand's own context.
  5. Errors: ClickException → rich_utils.rich_format_error or plain e.show() (core.py:203-212); typer.Exit/Abort are caught in _main (core.py:220-242).

Design decisions

Good

  1. Deferred construction (registration vs. build). Decorators only record CommandInfo/TyperInfo objects; the Click tree is compiled at app() time in get_command() (main.py:1173). This is what makes add_typer composition, recursive get_group_from_info (main.py:1283) and the three-level default resolution (solve_typer_info_defaults, main.py:1248) possible at all — sub-apps can be configured in any order, and the same Typer object can be reused by CliRunner and typer cli.
  2. The Default/DefaultPlaceholder sentinel (models.py:170-197). Because every Typer/TyperInfo parameter defaults to Default(x) instead of x, the library can distinguish "user passed None/False explicitly" from "user said nothing", which the precedence logic in solve_typer_info_defaults (main.py:1248-1280) and solve_typer_info_help (main.py:1211-1245) fundamentally depends on. A plain None sentinel would make help=None ambiguous.
  3. Vendoring + subclassing Click instead of monkey-patching it. Typer keeps a clean extension surface: TyperArgument.get_help_record (core.py:327) and TyperOption.get_help_record (core.py:752) return (name, help) tuples that both the plain formatter (_typer_format_options, core.py:861-879) and rich_utils consume, and default-string extraction was factored out of Click into _get_default_string (core.py:85-137) precisely so Rich help doesn't need regex hacks over Click's output. Vendoring also let Typer fix Click internals directly (e.g. TyperGroup.list_commands preserving creation order, core.py:1219-1221).

I would change

  1. The parameter-list duplication. The same ~20 settings are copy-pasted through Typer.__init__ (main.py:135-547), Typer.callback (main.py:549-751), Typer.add_typer (main.py:915-1131), TyperInfo (models.py:235-277), and ParameterInfo/OptionInfo/ArgumentInfo (models.py:280-617) — with full Doc() text repeated in params.py (1833 lines) and main.py. Adding one feature means touching 5+ giant signatures, and they already drift (e.g. deprecated defaults differ between Typer.command and TyperInfo). A shared dataclass/TypedDict plus reusable Doc constants would remove thousands of lines of copy-paste.
  2. The bidirectional coupling between _click and typer.core. The vendored Click imports typer.exceptions at module level (_click/core.py:19) and typer.core classes at runtime (_click/core.py:43, :757), while typer.core imports _click (core.py:16). This makes _click un-updatable from upstream Click (every sync must re-apply these edits) and forces fragile function-level imports to dodge cycles. I'd move Exit/Abort into _click.exceptions (re-exported by typer.exceptions) and have _click code duck-type on Parameter/Group APIs instead of importing TyperOption/ TyperGroup, keeping the dependency one-way.
