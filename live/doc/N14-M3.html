Typer — Architecture Notes

This repository is the Typer CLI framework (v0.27.x): a thin, type-hint-driven API on top of a vendored copy of Click (typer/_click/, forked from Click 8.3.1 — see typer/_click/__init__.py:1-3).

1. Main modules and dependencies

The code is organized in three layers. Dependencies point strictly downward (no module imports from a layer above it):

  public API        typer/__init__.py  (re-exports only)
                      |
  Typer layer       main.py  params.py  models.py  utils.py  completion.py
                      |                 |
  Typer core        core.py  exceptions.py  rich_utils.py  testing.py  cli.py
                      |
  vendored Click    typer/_click/  (core, parser, types, termui, ...)
                      |
  third-party       annotated_doc, rich (optional), shellingham, colorama
Module Role Depends on
typer/__init__.py Public API surface; re-exports Typer, Option, Argument, echo, Context, … main, params, models, exceptions, _click (typer/__init__.py:23-33)
typer/params.py Option() / Argument() factories. Pure data constructors returning OptionInfo / ArgumentInfo (typer/params.py:948-1002); heavily Doc-annotated for API docs. models, _click (types)
typer/models.py All the information dataclasses: CommandInfo (:200), TyperInfo (:235), ParameterInfo/OptionInfo/ArgumentInfo (:280), ParamMeta (:620), plus Context, File*, TyperPath (a click ParamType), and the Default()/DefaultPlaceholder sentinel (:170-197). _click (types, Context)
typer/utils.py Signature introspection: get_params_from_function() (:107) resolves Annotated[str, typer.Option()] hints into ParamMeta records, moving =-defaults and param_decls into the ParameterInfo; raises the four user-facing config errors (:22-92). models, _typing
typer/main.py The heart of the Typer layer. Typer class (registration only), the builder functions that convert registration data into a Click command tree, the Python-type → Click-type mapping, and the callback wrappers. models, core, utils, _click
typer/core.py Typer's Click subclasses: TyperCommand (:903), TyperGroup (:991), TyperOption (:435), TyperArgument (:245), plus the _main() entrypoint (:158) that adds rich error rendering, and help-record helpers shared with rich_utils. _click, exceptions, utils

Key dependency properties:

  • Typer instances never import core at runtime for building — building is done by free functions in main.py (get_command, main.py:1173).
  • models.py and params.py know nothing about main.py; the public decorators only record data.
  • rich_utils is deliberately isolated behind lazy imports so Rich can stay optional (core.py:27 reads TYPER_USE_RICH).

2. Request flow: decorated function → parsed command line

Using this app as the example:

import typer
app = typer.Typer()

@app.command()
def deploy(name: str, env: str = typer.Option("dev")):
    ...

app()

Phase A — Decorator time (pure registration, no parsing)

  1. typer.Option("dev") returns an OptionInfo dataclass (typer/params.py:948).
  2. @app.command() appends a CommandInfo(callback=deploy, ...) to app.registered_commands and returns the function untouched (typer/main.py:890-911). Nothing about signatures is inspected yet.

Phase B — app(): registration data → Click command tree

  1. Typer.__call__ (typer/main.py:1133) installs the pretty-except hook and calls get_command(self) (typer/main.py:1173).
  2. get_command decides the shape of the CLI: with one command and no callback/groups it builds a single command; otherwise a TyperGroup (typer/main.py:1176-1205). App-level --install-completion / --show-completion params are appended here (typer/main.py:1184-1186).
  3. get_group_from_info (typer/main.py:1283) recurses over registered_commands and registered_groups (nested Typer apps via add_typer, typer/main.py:1108), resolving inherited settings with the DefaultPlaceholder priority chain (solve_typer_info_defaults, typer/main.py:1248), then constructs a TyperGroup (typer/core.py:991).
  4. For each command, get_command_from_info (typer/main.py:1392): - derives the command name (get_command_name, :1360) and help text (explicit help → callback docstring, :1400-1404); - calls get_params_convertors_ctx_param_name_from_function (:1373), which for every function parameter runs get_params_from_function (typer/utils.py:107) — this is where Annotated[...] is split from the real annotation — and get_click_param (typer/main.py:1632).
  5. get_click_param decides option-vs-argument from the presence of OptionInfo/ArgumentInfo, maps the annotation to a Click ParamType via get_click_type (typer/main.py:1530: str→STRING, int→INT/ IntRange, Path→TyperPath, Enum→TyperChoice, …), picks the Python value convertor via determine_type_convertor (:1437, for Path, Enum, list, tuple), and emits a TyperOption / TyperArgument (typer/core.py:435 / :245) carrying the OptionInfo settings (help, envvar, callback, …).
  6. get_callback (typer/main.py:1496) wraps the user function: it builds a use_params dict keyed by the function's real parameter names, and at call time applies the convertors and injects click.Context if annotated (typer/main.py:1515-1524).

At the end of this phase there is an ordinary Click tree: a TyperGroup or TyperCommand whose params are TyperOption/TyperArgument objects.

Phase C — sys.argv → typed Python values

  1. The command's main() — TyperCommand.main (typer/core.py:955) — delegates to _main (typer/core.py:158), a Typer fork of click.main() that adds rich error output and typer.Exit/Abort handling (typer/core.py:203-242).
  2. make_context (typer/_click/core.py:687) creates the Context, merges context_settings, and calls parse_args.
  3. Command.parse_args (typer/_click/core.py:711) calls make_parser (:611), which asks each TyperOption.add_to_parser (typer/core.py:588) / TyperArgument.add_to_parser (typer/core.py:431) to register itself on Click's _OptionParser (typer/_click/parser.py:207).
  4. _OptionParser.parse_args (typer/_click/parser.py:275) tokenizes sys.argv[1:], matches long/short options and positional arguments, and returns raw option values.
  5. Back in parse_args, every parameter runs handle_parse_result (typer/_click/core.py:1051) — ordered by iter_params_for_processing (typer/_click/core.py:74) so is_eager params (e.g. --version, --help) are processed first.
  6. consume_value (typer/_click/core.py:920) resolves the value with a fixed precedence: command line → environment variable → default map → declared default (Typer extends the env layer with auto-envvar prefixes, typer/core.py:686-703, and prompts, typer/core.py:705-728).
  7. process_value (typer/_click/core.py:988) runs type_cast_value (:940) → the Click ParamType.convert() (e.g. TyperPath.convert, typer/models.py:696 — this is where exists=True validation and BadParameter errors happen), then the Typer param callback (wrapped by get_param_callback, typer/main.py:1797). The typed value lands in ctx.params[name].
  8. A TyperGroup then resolves the subcommand: TyperGroup.invoke (typer/core.py:1088) → resolve_command (typer/core.py:1171, which adds "Did you mean …?" suggestions, :1176-1186) → sub_ctx = cmd.make_context(...) (typer/core.py:1117) → the subcommand's parse_args runs again on the remaining tokens.
  9. Finally Command.invoke (typer/_click/core.py:729) does ctx.invoke(self.callback, **ctx.params) — the callback is the wrapper from step 8, which applies Path/Enum/list convertors (typer/main.py:1515-1524) and calls the original decorated function with fully typed arguments.

Errors unwind as ClickException subclasses (typer/_click/exceptions.py:20), are pretty-printed by _main (typer/core.py:203-212), and user code exceptions are filtered of Typer/Click frames by except_hook (typer/main.py:61-109).

3. Design review

Good decisions

  1. Registration and construction are fully separated. The Typer class only stores plain data — registered_commands, registered_groups, registered_callback (typer/main.py:545-547) — and the Click tree is built on demand by get_command (typer/main.py:1173). Consequences: sub-apps compose declaratively (add_typer, typer/main.py:1108); the test runner can rebuild a fresh tree per invoke (typer/testing.py:285); and root-level extras (completion options, typer/main.py:1184-1186) can be attached imperatively without touching the user's functions.
  2. The Default/DefaultPlaceholder sentinel + explicit resolution chain. Because None is a legitimate value, TyperInfo defaults are wrapped in DefaultPlaceholder (typer/models.py:170-197), and solve_typer_info_defaults (typer/main.py:1248-1280) documents the inheritance priority (app-level > add_typer > sub-app callback > sub-app constructor) in one place. This makes nested-app configuration predictable instead of implicit.
  3. Subclassing a vendored Click, not wrapping it. Typer subclasses _click.Command/_click.Parameter (TyperCommand typer/core.py:903, TyperOption typer/core.py:435) and keeps the token-level _OptionParser untouched. That gives battle-tested parsing for free while letting Typer override exactly its differentiators: rich help, flag help text, command-name suggestions (typer/core.py:1171-1186), and the is_bool_flag/--flag/--no-flag dual-declaration parsing (typer/core.py:547-586). Vendoring (rather than pinning a dependency) keeps this override surface stable across releases.

Decisions I would change

  1. Copy-pasted parameter surfaces in main.py. Typer.__init__, Typer.callback, Typer.command and Typer.add_typer each redeclare the same ~20 settings with hand-written Doc strings — roughly 1,000 lines of near-duplication (typer/main.py:135-519, :549-751, :753-913, :915-1131), plus the repeated options_metavar or self._info_val_str("options_metavar") idiom (typer/main.py:900-902, :1123-1125). A shared parameter-spec dataclass (or building the decorators from TyperInfo's own defaults) would shrink this dramatically and keep the four surfaces in sync.
  2. TyperOption.get_help_record duplicates Click's implementation "to modify a single line" (the comment says so — typer/core.py:752-754), and TyperGroup subclasses _click.Command instead of _click.Group, re-implementing parse_args/invoke (typer/core.py:1077-1119). These wholesale copies will silently drift from upstream Click; I would either contribute the needed behavior upstream, or override the narrow hooks (the secondary-opts join for bool flags, and collect_usage_pieces) instead of the whole methods.
