Typer Architecture

Typer (v0.27.3, typer/__init__.py:3) is a thin, type-hint-driven layer on top of a vendored copy of Click 8.3.1 (typer/_click/, see the header note in typer/_click/__init__.py:1-3). Users write plain Python functions with type annotations; Typer converts them into Click Command/Parameter objects at invocation time and delegates all parsing to Click's machinery.

Key dependency facts:

  • models.py is the shared vocabulary (data only, depends only on _click); params.py and main.py produce/consume those objects.
  • main.py is the only module that knows both worlds: it imports _click (main.py:21) and core (main.py:26) and translates between them.
  • core.py subclasses _click classes (TyperArgument(_click.core.Parameter), core.py:245; TyperCommand(_click.core.Command), core.py:903) and copies/patches their behavior (e.g. get_help_record duplicated at core.py:752, _main copied from click.Command.main at core.py:158-169).
  • Notably, TyperGroup extends Command, not Click's Group: group dispatch is re-implemented in Typer (core.py:991, invoke at core.py:1088, resolve_command at core.py:1171 with the "Did you mean" suggestion).
  • There is a deliberate circular edge: vendored _click imports back from typer.core (_click/core.py:757 imports ..core.TyperOption; _click/decorators.py:7 imports TyperGroup/TyperOption), resolved with lazy imports.
  • rich_utils.py is optional: everything is gated on HAS_RICH (core.py:27-32) and imported lazily (core.py:206-209, core.py:982).

Request flow: decorated function -> parsed command line

Registration (import time, does almost nothing):

  1. @app.command() (main.py:753) returns a decorator that only appends a CommandInfo data bag to app.registered_commands (main.py:890-911) and returns the original function. @app.callback() (main.py:549) and app.add_typer() (main.py:915) likewise just store TyperInfo objects. No Click object exists yet.

Build (first invocation):

  1. app() (main.py:1133) installs the pretty-traceback sys.excepthook (main.py:61) and calls get_command(self) (main.py:1173).
  2. get_command decides the shape: a TyperGroup if there is a callback, any sub-group, or >1 command; otherwise a single TyperCommand for the lone command (main.py:1176-1205). Completion options are appended to the root command here (main.py:1184-1186).
  3. get_command_from_info (main.py:1392) builds one command: - name: command_info.name or get_command_name(func.__name__) (lowercase, _->-, main.py:1360); help falls back to the docstring (main.py:1400-1404). - get_params_convertors_ctx_param_name_from_function (main.py:1373) calls utils.get_params_from_function (utils.py:107): inspect.signature(..., eval_str=True) + get_type_hints, then _split_annotation_from_typer_annotations (utils.py:94) peels Annotated[...] metadata, rejecting mixed Annotated/default styles (utils.py:115-160). Output: one ParamMeta (name, default, annotation) per function parameter. - get_click_param (main.py:1632) classifies each ParamMeta: ParameterInfo default -> that info; no default/Required -> ArgumentInfo (required); plain default -> OptionInfo (main.py:1641-1652). It unwraps Optional[X], list[X] (nargs=-1/multiple), tuple[...] (main.py:1665-1693), maps the annotation to a Click type via get_click_type (main.py:1530: STRING/INT/IntRange/BOOL/UUID/DateTime/TyperPath/File/ TyperChoice for Enums and Literals), and constructs a TyperOption/ TyperArgument (core.py:435/core.py:245). Bool options become --flag/--no-flag flags (main.py:1706-1719); user param callbacks and autocompletion functions are introspected and wrapped (main.py:1797, main.py:1849). - get_callback (main.py:1496) wraps the user function: the wrapper applies post-parse convertors for Path/Enum (main.py:1437), injects the Click Context if the function declares one (main.py:1522-1523), and calls the user function with exactly its declared parameters. - A TyperCommand/TyperGroup is instantiated with those params and wrapper callback (main.py:1411-1433, main.py:1329-1356). Group assembly is recursive over registered_commands/registered_groups, with per-field default resolution priorities (add_typer arg > sub-app callback > sub-app Typer() > default) done by solve_typer_info_defaults (main.py:1248).

Parse & invoke (per run):

  1. TyperCommand.main -> _main (core.py:158): takes sys.argv[1:] (expanded on Windows), detects the program name, handles shell-completion env-var requests early (core.py:182, core.py:882), then self.make_context(prog_name, args).
  2. Command.make_context (_click/core.py:687) creates a Context and calls parse_args (_click/core.py:711): make_parser builds an _OptionParser (_click/parser.py:207) by asking each param to add_to_parser (core.py:588 for options incl. flag/secondary opts, core.py:431 for arguments). parser.parse_args walks the raw argv and returns (opts, args, order).
  3. Each param is then finalized via handle_parse_result (_click/core.py:1051) in iter_params_for_processing order (eager first, _click/core.py:74): consume_value (command line -> env var incl. auto-env in core.py:686 -> defaults -> interactive prompt in core.py:705), type_cast_value (runs the ParamType.convert), required check, then the param callback; results land in ctx.params (_click/core.py:1076-1077).
  4. For groups, TyperGroup.parse_args (core.py:1077) keeps the first non-option token as the subcommand name; TyperGroup.invoke (core.py:1088) resolves it (resolve_command, core.py:1171, adding "Did you mean" suggestions when suggest_commands is on), invokes the group callback, then recurses into sub_ctx = cmd.make_context(...) / sub_ctx.command.invoke(sub_ctx).
  5. Command.invoke (_click/core.py:729) calls ctx.invoke(self.callback, **ctx.params) -> the get_callback wrapper -> the user's function.
  6. Failures are translated in _main (core.py:184-242): ClickException -> Rich-formatted usage error (rich_utils.rich_format_error), typer.Exit -> sys.exit(code), Abort -> "Aborted!", EOFError/KeyboardInterrupt mapped to exit codes; user-code tracebacks are filtered by except_hook (main.py:61).

Design decisions

Good

  1. Lazy, data-only registration. Decorators store plain data (CommandInfo, TyperInfo; main.py:890, main.py:729) and all Click objects are built on first call in get_command (main.py:1173). Importing a module with a Typer app has almost no cost, the app can still be mutated after decoration (more add_typer/command calls), the same function stays a normal callable, and tests like CliRunner.invoke (testing.py:275) get a fresh command tree per call.
  2. Default/DefaultPlaceholder sentinel (models.py:170-197). Because Typer merges settings from three levels (add_typer(...) > @sub_app.callback() > typer.Typer(...)), None/False can't double as "unset". The sentinel makes solve_typer_info_defaults (main.py:1248-1280) able to distinguish "explicitly set to None" from "not set", which is what makes the documented priority order actually work.
  3. Vendoring Click as typer._click. Typer's needs diverge hard from upstream Click: TyperGroup replaces click.Group entirely (core.py:991), _main is a forked copy (core.py:158), get_help_record is duplicated to tweak one line (core.py:752-755), and the parser/Parameter API was recently rewritten upstream. Vendoring pins the behavior, removes a dependency-version matrix, and lets Typer patch internals (e.g. _typer_param_setup_autocompletion_compat, core.py:45) without monkey-patching a third-party package at runtime.

Would change

  1. The 40-kwarg copy-paste cascade. The same giant keyword list is repeated in params.py overloads (1833 lines for two factories), ParameterInfo/OptionInfo/ ArgumentInfo (models.py:280-617), get_click_param (main.py:1632), TyperOption.__init__ (core.py:435), and again in Typer.__init__/callback/ add_typer/command (main.py:135-1131). Adding one option (e.g. atomic) touches ~6 files, and drift between copies is a standing bug source. I'd keep only the public typed overloads in params.py and have the internal layers carry a dataclass (or forward **kwargs into a single schema definition).
  2. Dead-but-advertised settings, and the reverse dependency from _click back into typer.core. chain is accepted by Typer/TyperInfo (main.py:217, models.py:245) but never reaches TyperGroup (get_group_from_info doesn't pass it, main.py:1329-1356) and its handling is commented out (core.py:1101), so chain=True silently does nothing. Relatedly, the vendored library imports its consumer (_click/core.py:757, _click/decorators.py:7, _click/core.py:543), making the layering circular and forcing lazy imports. I'd either implement or remove chain (and subcommand_metavar-style Click leftovers marked "you probably shouldn't use this"), and give _click.Command an option_class/group_class hook so the vendored core never imports typer.core.
