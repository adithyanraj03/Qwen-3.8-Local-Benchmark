10. HTTP/3 support

  • Gunicorn — not documented. Neither https://gunicorn.org/reference/settings/ nor https://gunicorn.org/guides/http2/ nor https://gunicorn.org/signals/ states any HTTP/3 support (HTTP/3 appears only in passing: "being deprecated in HTTP/3 and is rarely used in practice.").
  • Uvicorn — not documented. No page fetched (uvicorn.dev/settings/, /server-behavior/, /concepts/http2/, /concepts/http-protocols/) mentions HTTP/3.
  • Hypercorn — not documented. https://hypercorn.readthedocs.io/en/latest/ states support only up to HTTP/2:

    Hypercorn supports HTTP/1, HTTP/2, WebSockets (over HTTP/1 and HTTP/2), ASGI/2, and ASGI/3 specifications.

while the config table lists a QUIC bind option without documenting any HTTP/3 behavior:

| quic_bind | --quic-bind | The UDP/QUIC host/address to bind to. See bind for formatting options. | |

11. Graceful shutdown: how it works / controlling timeout

  • Gunicorn (signal behavior) — https://gunicorn.org/signals/

    TERM — graceful shutdown; waits for workers to finish requests up to graceful_timeout.

  • Gunicorn (timeout semantics) — https://gunicorn.org/reference/settings/

    Timeout for graceful workers restart in seconds. After receiving a restart signal, workers have this much time to finish serving requests. Workers still alive after the timeout (starting from the receipt of the restart signal) are force killed.

  • Gunicorn (default) — https://gunicorn.org/reference/settings/

    graceful_timeout¶ Command line: --graceful-timeout INT Default: 30

  • Uvicorn (mechanics) — https://uvicorn.dev/server-behavior/

    Uvicorn handles process shutdown gracefully, ensuring that connections are properly finalized, and all tasks have run to completion. During a shutdown period Uvicorn will ensure that responses and tasks must still complete within the configured timeout periods.

(same page, the intended sequence:)

Start a number of new server processes to handle incoming requests, listening on the existing socket. Stop the previous server processes from listening on the existing socket. Close any connections that are not currently waiting on an HTTP response, and wait for any other connections to finalize their HTTP responses. - Uvicorn (setting; no default stated) — https://uvicorn.dev/settings/ --timeout-graceful-shutdown <int> - Maximum number of seconds to wait for graceful shutdown. After this timeout, the server will start terminating requests.

(No Default: value is given for this option on the page — hence "default not documented".) - Hypercorn (mechanics + setting; default column blank) — https://hypercorn.readthedocs.io/en/latest/how_to_guides/configuring.html

Ambiguities and contradictions

  1. Gunicorn docs have moved. https://docs.gunicorn.org/en/stable/settings.html (and /en/latest/…, /signals) now 404 (docs.gunicorn.org redirects to gunicorn.org, which 404s the old paths). The current gunicorn.org docs describe a much newer Gunicorn than most third-party material: they document native HTTP/2 (--http-protocols, gunicorn[http2], h2c), which contradicts the widely repeated claim that "Gunicorn doesn't support HTTP/2". They also give keep-alive default 2 s, whereas older Gunicorn docs stated 5 s.
  2. Gunicorn's default bind is conditional. 127.0.0.1:8000 applies only when the PORT environment variable is unset; then it is 0.0.0.0:$PORT. The settings page states both in one entry.
  3. Gunicorn keep-alive is worker-class-dependent. The default sync worker "does not support persistent connections and will ignore this option", so the 2 s default applies only to gthread/gevent/asyncio-style workers.
  4. Hypercorn's config table leaves defaults blank for bind and graceful_timeout (and others), while the prose Binds guide states the bind default (127.0.0.1:8000). For graceful_timeout the table's own "Purpose" cell is truncated mid-sentence ("…for any remaining requests (tasks) to") in both the rendered HTML and the upstream configuring.rst.txt, and no default is given anywhere — so Hypercorn's graceful timeout default is reported as "not documented".
  5. Hypercorn's --quic-bind vs. "supports HTTP/1, HTTP/2". The options table exposes a UDP/QUIC bind, implying QUIC plumbing, but no fetched page documents HTTP/3 request serving; the front page's support list stops at HTTP/2. Treated as "not documented".
  6. Uvicorn's --timeout-graceful-shutdown has no documented default, even though the settings page documents defaults for most other options. The Server Behavior page describes shutdown ("responses and tasks must still complete within the configured timeout periods") but never names a default or which OS signals trigger shutdown.
  7. "Worker timeout" is not a like-for-like concept. Gunicorn's timeout kills/restarts silent workers (heartbeat-based, since 26.3.0 also cancelling stalled HTTP/2 streams); Uvicorn's --timeout-worker-healthcheck bounds healthcheck responses only; Hypercorn documents no worker timeout at all. Any comparison here is approximate.
  8. Uvicorn worker defaults differ in wording from Gunicorn's ("Defaults to the $WEB_CONCURRENCY environment variable if available, or 1" vs Gunicorn's "Default: 1 … By default, the value of the WEB_CONCURRENCY environment variable…"), but the effective semantics as documented are the same.
  9. HTTP/2 in Uvicorn is doubly experimental (zttp parser "not suited for production usage" plus HTTP/2 "not enabled by default"), whereas Hypercorn negotiates h2 over TLS by default with no CLI flag and Gunicorn requires an explicit opt-in flag — three different "on-by-default" philosophies that make a single "HTTP/2: yes/no" cell misleading.
