\title{\Large\bfseries Speculative Decoding on Mixture-of-Experts Models with Offloaded Experts: A Cost Model}
\author{Anonymous Author\thanks{Preprint. Cost-model study; all numerical results are generated from the released model script.}}
\date{}
\maketitle
\begin{abstract}
Speculative decoding accelerates autoregressive inference by drafting several
tokens and verifying them in a single pass of the target model. For dense
models the verification cost is nearly independent of the draft length, so
the analysis of speculation reduces to a trade-off between draft latency and
token acceptance rate. Mixture-of-Experts (MoE) models served with a portion
of their experts offloaded to host memory break this assumption: verifying a
block of draft tokens activates the \emph{union} of the experts routed to by
every token in the block, so verification cost grows with draft length
through expert-cache misses serviced over a slow host link. We present a
closed-form cost model for speculative decoding under expert offloading that
couples the acceptance rate, the routing overlap between adjacent draft
tokens, the expert-cache hit rate, and the bandwidths of accelerator memory
and the host link. The model yields a minimum acceptance-rate threshold for
speculation to pay off, a miss-dominated regime in which the optimal draft
length is bounded in closed form, and monotone comparative statics for the
draft budget. We instantiate the model as SpecOff, an online policy that
selects the draft budget from measured statistics, and evaluate it numerically
on a DeepSeek-V3-class configuration. The model reproduces the reported
failures of fixed-length speculation on MoE models (slowdowns below $1\times$)
and predicts up to $2.4\times$ speedup when offloading latency is hidden,
in qualitative agreement with recent systems.
\end{abstract}
\begin{keywords}
speculative decoding, mixture-of-experts, expert offloading, cost model, LLM inference.
\end{keywords}

\section{Introduction}
\label{sec:intro}

Autoregressive decoding is the latency bottleneck of large language model
(LLM) serving: each output token requires a full pass over the model, and
throughput is bounded by weight movement rather than arithmetic~\cite%
{pope2023efficiently,williams2009roofline}. Speculative
decoding~\cite{leviathan2023fast,chen2023accelerating} attacks this
bottleneck by letting a cheap \emph{draft} model propose $\gamma$ tokens
which the \emph{target} model verifies in one parallel pass; with a
suitable acceptance rule the output distribution is preserved exactly, and
multiple tokens are amortized over a single target forward. A large body of
work improves drafting through self-speculation, multi-head decoding, and
feature-level
extrapolation~\cite{zhang2024draft,cai2024medusa,li2024eagle,he2024rest,miao2024specinfer}.

All of these methods share an implicit assumption: the cost of a
verification step is essentially independent of how many tokens are
verified, because a dense model reads all of its weights on every step.
This assumption fails for Mixture-of-Experts (MoE)
models~\cite{shazeer2017outrageously,fedus2022switch,lepikhin2021gshard,jiang2024mixtral},
whose per-token cost is proportional to the weights of the $k$ experts each
token routes to. When the model exceeds accelerator memory---as frontier MoE
models routinely do---serving systems keep only a subset of experts resident
and stream the rest from host memory or
disk~\cite{sheng2023flexgen,song2024powerinfer,tang2024hobbit,kwon2023vllm}.
In this setting a draft block of $\gamma{+}1$ tokens activates the
\emph{union} of experts requested by all tokens in the block. If adjacent
draft tokens route to disjoint experts, verification traffic grows with the
draft length, and every expert-cache miss is serviced over a host link that
is one to two orders of magnitude slower than accelerator
memory~\cite{wang2025specmoeoff,saxena2025cascade}. Speculation can
therefore be useless or even actively harmful for MoE models, in sharp
contrast with the dense case.

Two recent systems demonstrate that the picture is not uniformly negative.
Cascade~\cite{saxena2025cascade} measures ``speculation utility'' online
and disables fixed-length speculation when it would slow decoding,
reporting that naive speculation on MoE models can incur up to
$1.5\times$ slowdown. SpecMoEOff~\cite{wang2025specmoeoff} instead
\emph{hides} offloading latency behind speculation, orchestrating CPU and
GPU so that expert streaming overlaps with draft execution, and reports up
to $2.5\times$ decode-throughput improvement. These are point designs:
neither provides an analytical account of \emph{when} speculation helps,
by how much, and what draft length a deployment should choose. That is the
gap this paper fills.

\subsection*{Contributions}
This paper makes the following contributions.
\begin{enumerate}
  \item A closed-form cost model for speculative decoding on MoE models
    with offloaded experts (Section~\ref{sec:model}) that couples the
    acceptance rate $\alpha$, the routing overlap $\rho$ between adjacent
    draft tokens, the expert-cache hit rate $h$, and the bandwidths of
    accelerator memory and the host link.
  \item Structural results: a minimum acceptance-rate threshold for
    speculation to pay off (Proposition~\ref{prop:threshold}), a
    miss-dominated regime with a closed-form upper bound on the optimal
    draft length (Proposition~\ref{prop:missdom}), and monotone
    comparative statics for the draft budget (Proposition~\ref{prop:statics}).
  \item SpecOff (Section~\ref{sec:algorithm}), a deployment-oriented
    algorithm that selects the draft budget online by minimizing the
    predicted per-token latency of the cost model under measured
    statistics, with $O(\Gamma_{\max})$ work per decision.
  \item A numerical evaluation and regime maps
    (Sections~\ref{sec:methodology}--\ref{sec:results}) on a
    DeepSeek-V3-class configuration that quantify when speculation helps
    or hurts, and that reproduce the qualitative behavior of published
    MoE speculative-decoding systems.
\end{enumerate}

Section~\ref{sec:related} positions the model against prior work.
Section~\ref{sec:model} develops the cost model.
Section~\ref{sec:algorithm} presents SpecOff.
Sections~\ref{sec:methodology} and~\ref{sec:results} describe the
methodology and results. Section~\ref{sec:discussion} discusses
limitations, and Section~\ref{sec:conclusion} concludes.

\section{Related Work}
\label{sec:related}

\subsection*{Speculative decoding}
Leviathan et al.~\cite{leviathan2023fast} and Chen et
al.~\cite{chen2023accelerating} introduced speculative decoding and the
modified-rejection acceptance rule; both analyze speedup purely in terms
of acceptance rate and draft/target cost ratios, assuming a constant
verification cost. SpecInfer~\cite{miao2024specinfer} generalizes drafting
to token trees and explicitly targets offloaded dense models, but treats
the offloaded target as a monolith whose cost does not depend on the
verified token set. Medusa~\cite{cai2024medusa},
EAGLE~\cite{li2024eagle}, and self-speculative
drafting~\cite{zhang2024draft} improve draft quality;
REST~\cite{he2024rest} replaces the draft model with retrieval. None of
these model the input-dependent verification cost of a sparse target.

\subsection*{MoE inference and expert offloading}
Sparsely-gated MoE layers~\cite{shazeer2017outrageously} and their large
deployments~\cite{lepikhin2021gshard,fedus2022switch,jiang2024mixtral}
decouple parameter count from per-token compute, which makes weight
\emph{movement}, not FLOPs, the serving bottleneck. General LLM serving
systems manage KV-cache memory~\cite{kwon2023vllm} or offload weights
across GPU, CPU, and disk tiers~\cite{sheng2023flexgen};
PowerInfer~\cite{song2024powerinfer} exploits activation locality to keep
hot parameters resident. For MoE models specifically, expert offloading
systems cache a hot subset of experts and stream misses;
HOBBIT~\cite{tang2024hobbit} reduces miss cost with mixed-precision
experts and prefetching, and Liang et al.~\cite{liang2025notall} show
that the routing locality these systems rely on varies strongly across
models. The analytical side is thinner: Pope et al.~\cite%
{pope2023efficiently} derive a roofline-style model for \emph{dense}
transformer inference, building on the classical roofline
model~\cite{williams2009roofline}, but do not treat sparse expert
activation.

\subsection*{Speculation combined with MoE}
Closest to this work, Cascade~\cite{saxena2025cascade} observes
empirically that draft tokens collectively activate more weights, inflating
verification time by $2$--$3\times$ on MoE models, and tunes speculation
online by measured utility. SpecMoEOff~\cite{wang2025specmoeoff} enlarges
the per-expert workload with speculation and hides offloading latency
through CPU--GPU orchestration. Both are systems papers: their design
decisions (when to speculate, how long to draft, how much to hide) are
tuned empirically. In contrast, this paper provides an explicit cost model
whose parameters are measurable hardware and routing statistics, derives
closed-form conditions and bounds, and turns the model into a
decision procedure (SpecOff). We expect the model to serve the same role
for MoE speculation that the acceptance-rate analysis of
Leviathan et al.~\cite{leviathan2023fast} served for dense speculation:
a design tool that explains observed speedups and failures and predicts
them before implementation.

\section{Cost Model}
\label{sec:model}

\subsection*{Setup and assumptions}
Consider an MoE target model with $L$ layers, $E$ routed experts per
layer, and top-$k$ routing. Let $s_e$ denote the total bytes of one
expert slot summed over all layers, and $s_a$ the bytes of all
non-expert weights (attention, routers, shared components), which are
assumed resident. The accelerator has HBM bandwidth $B_h$ and peak
compute $P$; the host link has bandwidth $B_c \ll B_h$. A dense draft
model produces one token in time $t_d$; the target model costs $f$ FLOPs
per token. The verifier processes a block of $n=\gamma{+}1$ tokens in one
pass. Table~\ref{tab:notation} summarizes the notation.

The model rests on five assumptions, each supported by the cited
literature and revisited in Section~\ref{sec:discussion}.
\begin{enumerate}
  \item[(A1)] \emph{Acceptance.} Each draft token is accepted
    independently with probability $\alpha$, as in the standard analysis
    of speculative decoding~\cite{leviathan2023fast,chen2023accelerating}.
  \item[(A2)] \emph{Routing mean-field.} Each additional token in a
    verified block adds $k(1-\rho)$ new experts in expectation, where
    $\rho \in [0,1]$ is the probability that a routed expert slot is
    already covered by the block's union. Adjacent tokens share experts
    with probability $\rho>0$ because of routing locality
    observed in practice~\cite{liang2025notall,song2024powerinfer}.
  \item[(A3)] \emph{Cache pressure.} The hit probability of the union
    decays linearly with its excess size beyond the single-token working
    set, with slope $\tau$ per expert; $\tau=0$ corresponds to an
    idealized cache that absorbs the whole union.
  \item[(A4)] \emph{Roofline verification.} A verification step takes
    the maximum of its compute time and its resident-memory traffic
    time~\cite{williams2009roofline,pope2023efficiently}, plus any
    expert-streaming traffic that the system fails to overlap with
    computation. A fraction $\psi \in [0,1]$ of miss traffic is hidden
    by prefetching or CPU co-execution during the draft
    phase~\cite{wang2025specmoeoff,tang2024hobbit}.
  \item[(A5)] \emph{Serial drafting.} Draft tokens are produced one at
    a time; the draft phase cannot overlap with target verification.
\end{enumerate}

\subsection*{Draft acceptance}
Under (A1) the expected number of accepted tokens per speculation round,
including the bonus token emitted when a draft is rejected, is the
standard truncated-geometric mean
\begin{equation}
A(\gamma)=\frac{1-\alpha^{\gamma+1}}{1-\alpha},
\qquad A(0)=1.
\label{eq:accept}
\end{equation}

\subsection*{Expert union, hits, and misses}
Under (A2) the expected union of experts activated per layer when
verifying a block of $\gamma{+}1$ tokens is
\begin{equation}
U(\gamma)=\min\{E,\; k+\gamma\,k\,(1-\rho)\}.
\label{eq:union}
\end{equation}
Under (A3) the hit probability of a union of size $u$ is
\begin{equation}
h(u)=\min\{1,\ \max\{0,\ h_0-\tau\,(u-k)\}\},
\label{eq:hit}
\end{equation}
so the expected number of expert misses per layer in a round is
\begin{equation}
M(\gamma)=U(\gamma)\,\bigl(1-h(U(\gamma))\bigr).
\label{eq:miss}
\end{equation}
Equations~\eqref{eq:union}--\eqref{eq:miss} are the crux of the
departure from dense speculative decoding: verification cost becomes an
increasing function of the draft length.

\subsection*{Verification, round time, and per-token latency}
Under (A4), the compute time, resident-traffic time, and exposed
miss-traffic time of a verification round are
\begin{align}
t_c(\gamma)&=\frac{(\gamma+1)\,f}{P}, \label{eq:comp}\\
t_r(\gamma)&=\frac{s_a+\bigl(U(\gamma)-M(\gamma)\bigr)\,s_e}{B_h},
\label{eq:res}\\
t_m(\gamma)&=(1-\psi)\,\frac{M(\gamma)\,s_e}{B_c}. \label{eq:misslat}
\end{align}
The verification latency is
\begin{equation}
t_v(\gamma)=\max\{t_c(\gamma),\,t_r(\gamma)\}+t_m(\gamma),
\label{eq:verify}
\end{equation}
and the round time adds the serial draft phase,
\begin{equation}
T(\gamma)=\gamma\,t_d+t_v(\gamma).
\label{eq:round}
\end{equation}
The expected per-token latency and the speedup over autoregressive
decoding ($\gamma=0$) are
\begin{equation}
\ell(\gamma)=\frac{T(\gamma)}{A(\gamma)},
\qquad
S(\gamma)=\frac{\ell(0)}{\ell(\gamma)}.
\label{eq:speedup}
\end{equation}
The optimal draft budget is
\begin{equation}
\gamma^{*}=\operatorname*{arg\,min}_{\gamma\in\{0,\dots,\Gamma_{\max}\}}
\ \ell(\gamma).
\label{eq:opt}
\end{equation}

\subsection*{Structural results}
Write $\Delta = k(1-\rho)\,s_e/B_h$ for the marginal resident-traffic
cost of one additional draft token, and $m_0 = M(0)=k(1-h_0)$ for the
baseline miss count.

\begin{proposition}[Threshold for speculation]
\label{prop:threshold}
Assume $h_0=1$ (no expert misses) and memory-bound verification with
$U(\gamma)<E$. Then $t_v(\gamma)=t_v(0)+\gamma\,\Delta$, and
$S(\gamma)>1$ if and only if
\begin{equation}
\gamma\,(t_d+\Delta) \;<\; \bigl(A(\gamma)-1\bigr)\,t_v(0).
\label{eq:threshold}
\end{equation}
\end{proposition}
\begin{proof}
With $M\equiv 0$, $t_v(\gamma)=t_r(\gamma)=t_r(0)+\gamma\Delta$ is
affine in $\gamma$, and $T(0)=t_v(0)$. Substituting into
$S(\gamma)>1 \iff T(\gamma)<A(\gamma)\,T(0)$ gives
\eqref{eq:threshold}.
\end{proof}

\begin{corollary}[Acceptance floor]
\label{cor:floor}
For fixed hardware and workload, $A(\gamma)$ is strictly increasing in
$\alpha$, so \eqref{eq:threshold} holds if and only if
$\alpha>\alpha_{\min}(\gamma)$, where $\alpha_{\min}(\gamma)\in(0,1)$
is the unique root of \eqref{eq:threshold} with equality.
$\alpha_{\min}$ is increasing in $t_d$ and $\Delta$, and decreasing in
the baseline verification cost $t_v(0)$.
\end{corollary}

Corollary~\ref{cor:floor} is the MoE analogue of the classical
acceptance-rate requirement of speculative decoding, with one decisive
difference: $\Delta>0$ only because the target is sparse. For a dense
model, $U$ is constant and the resident term does not grow with $\gamma$.

\begin{proposition}[Miss-dominated regime]
\label{prop:missdom}
Assume $\tau=0$, $U(\gamma)<E$, and that exposed miss traffic dominates
verification time, i.e., $t_m(0)\gg\max\{t_c(0),t_r(0)\}$. Then
\begin{equation}
S(\gamma)\;\approx\;\frac{A(\gamma)}{1+\gamma\,(1-\rho+c)},
\qquad
c=\frac{t_d\,B_c}{(1-\psi)\,m_0\,s_e},
\label{eq:missdom}
\end{equation}
and $S(\gamma)>1$ requires $A(\gamma)>1+\gamma\,(1-\rho+c)$.
Consequently any beneficial budget obeys
\begin{equation}
\gamma^{*}\;\le\;
\left\lceil \frac{1}{1-\alpha}\cdot\frac{1}{\,1-\rho+c\,}\right\rceil .
\label{eq:bound}
\end{equation}
\end{proposition}
\begin{proof}
With $\tau=0$, $M(\gamma)=m_0\,U(\gamma)/k=m_0\,(1+\gamma(1-\rho))$,
so $t_m(\gamma)=(1-\psi)\,m_0 s_e(1+\gamma(1-\rho))/B_c$. Dropping the
dominated terms in \eqref{eq:verify} and substituting into
\eqref{eq:speedup} with $T(0)\approx t_m(0)$ yields
\eqref{eq:missdom}. Since $A(\gamma)\le \tfrac{1}{1-\alpha}$ for all
$\gamma$, feasibility of $A(\gamma)>1+\gamma(1-\rho+c)$ gives
\eqref{eq:bound}.
\end{proof}

\begin{proposition}[Comparative statics]
\label{prop:statics}
In the regime of Proposition~\ref{prop:missdom}, the optimal budget
$\gamma^{*}$ is non-decreasing in $\alpha$, $\rho$, and $\psi$, and
non-increasing in $t_d$ and $B_c$. For $\tau>0$, $\gamma^{*}$ is
further reduced because $M(\gamma)$ becomes superlinear in $\gamma$.
\end{proposition}
\begin{proof}[Proof sketch]
By \eqref{eq:missdom}, $S(\gamma)>1$ is equivalent to
$A(\gamma)>1+\gamma(1-\rho+c)$. The left side is increasing in $\alpha$;
the right side is decreasing in $\rho$ and increasing in $c\propto
t_d/B_c$ and decreasing in $\psi$ through $(1-\psi)^{-1}$. Hence the
feasible set of $\gamma$ expands monotonically with $\alpha,\rho,\psi$
and contracts with $t_d,B_c$, which is preserved under taking the
maximal feasible budget. For $\tau>0$, \eqref{eq:hit}--\eqref{eq:miss}
give $M(\gamma)\ge m_0(1+\gamma(1-\rho))$ with strict inequality once
$h$ is not clamped, which lowers $S(\gamma)$ for large $\gamma$ and
shrinks $\gamma^{*}$.
\end{proof}

Propositions~\ref{prop:threshold}--\ref{prop:statics} explain the
published behavior of MoE speculative-decoding systems. The bound
\eqref{eq:bound} says long drafts are only viable when acceptance is
high \emph{and} adjacent draft tokens reuse experts ($\rho$ high) or the
link is slow relative to drafting ($c$ small, i.e., large $m_0 s_e$ or
large $\psi$)---exactly the operating point SpecMoEOff engineers
through CPU co-execution~\cite{wang2025specmoeoff}. Conversely, when
$\rho$ is low and $\psi\approx 0$, \eqref{eq:missdom} gives
$S(\gamma)<1$ for every $\gamma\ge 1$ at moderate $\alpha$, matching
the slowdowns that Cascade exists to avoid~\cite{saxena2025cascade}.

\section{SpecOff: Choosing the Budget from the Model}
\label{sec:algorithm}

The cost model becomes a policy. SpecOff maintains exponentially
weighted moving-average estimates of the acceptance rate $\hat\alpha$,
the routing overlap $\hat\rho$, and the single-token hit rate
$\hat h_0$ from the serving engine's own counters, and periodically
selects the budget minimizing predicted latency, as shown in
Algorithm~\ref{alg:specoff}. Hardware parameters
($s_e,s_a,B_h,B_c,P,f,t_d,\tau,\psi$) are measured once offline;
$\hat\psi$ may be re-estimated from the observed fraction of offload
time that overlaps with compute. A hysteresis band of $\eta$ prevents
budget oscillation when two budgets are statistically tied.

\begin{algorithm}[t]
\caption{SpecOff: online draft-budget selection}
\label{alg:specoff}
\KwIn{hardware parameters $\theta=(s_e,s_a,B_h,B_c,P,f,t_d,\tau,\psi)$;
  max budget $\Gamma_{\max}$; hysteresis $\eta$; decay $\beta$}
\KwOut{draft budget $\gamma$ used for the next round}
initialize $\hat\alpha\leftarrow 0.8$, $\hat\rho\leftarrow 0.5$,
  $\hat h_0\leftarrow 0.9$, $\gamma\leftarrow 0$\;
\While{serving}{
  run one round with budget $\gamma$\;
  observe accepted tokens $a$, union sizes $u_t$, cache hits\;
  update $\hat\alpha\leftarrow\beta\hat\alpha+(1-\beta)\,\frac{a-1}{\gamma+1}$\;
  update $\hat\rho$, $\hat h_0$ by EMA of observed overlap and hit rates\;
  \If{decision tick}{
    \For{$g\leftarrow 0$ \KwTo} $\Gamma_{\max}$}{
      compute $\hat U(g),\hat M(g)$ by \eqref{eq:union}--\eqref{eq:miss}
        with $(\hat\alpha,\hat\rho,\hat h_0)$\;
      $\hat\ell(g)\leftarrow\bigl(g\,t_d+\hat t_v(g)\bigr)/\hat A(g)$
        \tcp*{cost model}}
    $g'\leftarrow\arg\min_g \hat\ell(g)$\;
    \lIf{$|\hat\ell(\gamma)-\hat\ell(g')|>\eta\,\hat\ell(\gamma)$}
      {$\gamma\leftarrow g'$}
  }
}
\end{algorithm}

Each decision scans $\Gamma_{\max}{+}1$ closed-form expressions, so the
policy adds negligible overhead to a decoding step whose cost is
milliseconds. The estimates $\hat\alpha,\hat\rho,\hat h_0$ are exactly
the quantities modern serving engines already log for scheduling and
cache management~\cite{saxena2025cascade,tang2024hobbit}, so SpecOff
requires no extra instrumentation.

\section{Methodology}
\label{sec:methodology}

This paper evaluates the cost model numerically: all figures and tables
are produced by evaluating \eqref{eq:accept}--\eqref{eq:opt} on a grid
of model parameters, using a released script that implements the model
exactly as written. We do not run new hardware experiments; instead we
calibrate the model to a published, realistic configuration and compare
its \emph{predictions} against the \emph{measured behavior} of recent
systems.

\subsection*{Calibrated configuration}
Table~\ref{tab:params} lists the default parameters, chosen to
represent a DeepSeek-V3-class MoE model~\cite{jiang2024mixtral} served
on a single A100-80GB accelerator with 4-bit expert
quantization~\cite{sheng2023flexgen} over PCIe Gen4. Expert sizes are
computed from the architecture ($3$ matrices of $7168\times 2048$
parameters per expert-layer, $58$ layers, $0.5$\,B/parameter); the
non-expert footprint aggregates attention, shared experts, dense layers,
and embeddings. The draft model is a $1$B-parameter dense model, whose
single-token latency is its weight-read time at HBM bandwidth. Roofline
parameters follow published measurements~\cite{pope2023efficiently}.
The behavioral parameters $\alpha,\rho,h_0,\tau,\psi$ are swept over
the ranges reported or implied in the literature: acceptance rates of
strong drafters span $0.6$--$0.9$~\cite{li2024eagle,cai2024medusa};
routing locality is model-dependent but substantial
\cite{liang2025notall}; offloading systems report high hit rates for
cached hot experts~\cite{tang2024hobbit} and partial hiding of miss
traffic~\cite{wang2025specmoeoff}.

\subsection*{Metrics and sweeps}
For each parameter vector we compute $S(\gamma)$ for
$\gamma\in\{0,\dots,16\}$ and report (i) normalized per-token latency
$\ell(\gamma)/\ell(0)$, (ii) the best achievable speedup
$\max_\gamma S(\gamma)$ with its budget $\gamma^{*}$, and (iii) the
speedup of \emph{fixed}-length speculation, $S(4)$, which is the
deployment style that naive systems adopt. Sweeps are over
$\alpha$ and $h_0$ (Tables~\ref{tab:fixed} and~\ref{tab:optimal}),
over $h_0$ and $\psi$ (Fig.~\ref{fig:hitrate}), and over $\alpha$ and
$\rho$ (Fig.~\ref{fig:gamma}). Unless stated otherwise, defaults are
$\rho=0.7$, $\tau=0.005$, $h_0=0.9$, $\psi=0.9$.

\subsection*{Validation protocol}
We validate the model on three published observations rather than
absolute latencies: (1) Cascade reports that fixed-$K$ speculation on
MoE models inflates verification traffic and can slow decoding by up to
$1.5\times$~\cite{saxena2025cascade}; the model must exhibit
$S(\gamma)<1$ regions. (2) SpecMoEOff reports up to $2.5\times$ decode
throughput gains when offloading latency is hidden behind
speculation~\cite{wang2025specmoeoff}; the model must admit large
speedups only when $\psi$ is high. (3) Expert-offloading systems
achieve good performance only with high cache hit
rates~\cite{tang2024hobbit,liang2025notall}; the model's optimum must
shift with $h_0$ and $\tau$ in the corresponding direction.

\subsection*{Latency versus draft length}
Fig.~\ref{fig:latency} shows normalized per-token latency as a function
of the draft length for three acceptance rates. Every curve is
U-shaped: short drafts amortize the fixed verification cost, but beyond
$\gamma^{*}$ the growing expert union and exposed miss traffic dominate,

$\alpha=0.5$ the minimum sits at $\gamma^{*}=1$ and $S$ never exceeds
$1.2\times$; at $\alpha=0.9$, $\gamma^{*}=4$ and the speedup reaches
$1.9\times$. The figure makes Corollary~\ref{cor:floor} concrete: the
acceptance floor rises steeply with $\gamma$, so a system that fixes
$\gamma=4$ without checking $\alpha$ operates below the floor for weak
drafters.

\subsection*{Fixed-length speculation: the failure mode}
Table~\ref{tab:fixed} reports $S(4)$, the speedup of a system that

speculation when measured utility drops below one~\cite{saxena2025cascade},
and it shows why a deployment cannot tune $\gamma$ without also
estimating $\alpha$ and $\psi$.

\subsection*{Check against published behavior}
All three validation targets are met. (1) The model produces slowdown
regions for fixed-length speculation at moderate $\alpha$ and high $h_0$
(Table~\ref{tab:fixed}, lower block), consistent with the up-to-$1.5\times$
slowdowns motivating Cascade~\cite{saxena2025cascade}. (2) Large
speedups appear only when miss traffic is hidden ($\psi\ge 0.5$) and
locality is high, with a maximum of $2.39\times$ at $\alpha{=}0.9$,
$\rho{=}0.8$---the operating point SpecMoEOff
targets~\cite{wang2025specmoeoff}. (3) The optimum shifts toward
larger $\gamma^{*}$ as $\tau$ grows only when the cache can absorb the
union, and toward $\gamma^{*}=0$ as locality degrades, matching the
model-dependence of routing consistency reported
by Liang et al.~\cite{liang2025notall}. Absolute latencies are not
validated; the model is intended for relative predictions and design
guidance.

%======================================================
\section{Discussion and Limitations}
\label{sec:discussion}

\textbf{Mean-field routing.} A2 and A3 replace the joint routing
distribution of a draft block with a mean-field union-size recursion.
Real routers exhibit bursty, layer-correlated reuse: a token discussing
a code symbol may keep the same expert active for dozens of steps,
violating the constant-$\rho$ assumption in both directions. The model
should be read as predicting medians and regime boundaries, not
per-request latencies; the tails it omits are exactly what a scheduler
with hysteresis (Algorithm~\ref{alg:specoff}) must absorb.

\textbf{Stationary statistics.} $\alpha$, $\rho$, and $h_0$ drift
within a request (code vs.\ prose sections) and across requests.
SpecOff tracks them with exponential smoothing, but the analysis assumes
stationarity; rapid regime switches will cause transient mis-selection.

\textbf{Lumped hiding parameter.} $\psi$ compresses prefetch scheduling,
CPU co-execution, and multi-stream overlap into one number. In
reality the hidden fraction depends on the ratio of compute slack to
transfer volume and on contention with concurrent requests; a more
faithful treatment would model the host link as a queueing resource.

\textbf{Cache coupling.} We treat $h_0$ as an exogenous parameter, but
a deployment fixes a cache capacity $C$, and speculation enlarges the
working set $U(\gamma^{*})$, which feeds back into $h_0$. The
fixed-point coupling of $C$, $\gamma^{*}$, and $h_0$ is a natural
extension; the $\tau$ term is a first-order proxy for it.

\textbf{Scope.} The model covers single-request, single-accelerator
decoding with a dense drafter and exact verification. Batching (which
changes the roofline balance), tree-based drafting (which changes the
union recursion \eqref{eq:union}), shared experts, quantization
dynamics~\cite{tang2024hobbit}, and multi-GPU expert
parallelism~\cite{miao2024specinfer,jiang2024mixtral} are outside its
scope. The calibration in Table~\ref{tab:params} is illustrative; the
structural conclusions depend only on the ordering $B_c \ll B_h$ and
$\rho<1$, not on specific hardware numbers.

%======================================================
\section{Conclusion}
\label{sec:conclusion}

Speculative decoding on MoE models with offloaded experts violates the
constant-verification-cost assumption inherited from the dense-model
literature. A closed-form cost model that couples acceptance rate,
routing overlap, expert-cache hit rate, and the memory hierarchy
explains both observed failure modes---fixed-length speculation that
slows decoding, and speculation that nearly triples decode throughput
when offloading latency is hidden---and yields actionable rules:
estimate $\alpha$ and $\rho$ before choosing $\gamma$; prefer hiding
infrastructure over longer drafts; and switch speculation off when
locality is low. SpecOff turns the model into an online policy at
negligible cost. Future work includes the cache-capacity fixed point,
tree-structured drafts under expert-union cost, and end-to-end
validation against serving engines.
