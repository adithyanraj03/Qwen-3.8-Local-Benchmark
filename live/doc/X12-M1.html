Gunicorn vs Uvicorn vs Hypercorn — official documentation comparison

Method: every value below was taken only from official documentation pages fetched live during this session (2026-10-10). Each value is followed by its citation (exact URL + verbatim quote). Where a fetched page does not state a value, it is marked not documented.

Official documentation sources used:

  • Gunicorn: https://gunicorn.org (Reference → Settings, Run, Signals, Guides → HTTP/2)
  • Uvicorn: https://uvicorn.dev (Settings, Server Behavior, Concepts → HTTP/2, Deployment, Index)
  • Hypercorn: https://hypercorn.readthedocs.io/en/latest/ (Configuring, Binds, Discussions → HTTP/2, Workers, Index). Note: hypercorn.org returned transport errors from this machine; Read the Docs is the project's official documentation host.

Citations

Gunicorn

G1. Default bind address and port — https://gunicorn.org/reference/settings/ (settings bind)

"Command line: -b ADDRESS, --bind ADDRESS" "Default: ['127.0.0.1:8000']" "If the PORT environment variable is defined, the default is ['0.0.0.0:$PORT']. If it is not defined, the default is ['127.0.0.1:8000']."

G2. Default number of workers — https://gunicorn.org/reference/settings/ (settings workers)

"Command line: -w INT, --workers INT" "Default: 1" "By default, the value of the WEB_CONCURRENCY environment variable, which is set by some Platform-as-a-Service providers such as Heroku. If it is not defined, the default is 1."

G3. Default worker timeout — https://gunicorn.org/reference/settings/ (settings timeout)

"Command line: -t INT, --timeout INT" "Default: 30" "Workers silent for more than this many seconds are killed and restarted."

G4. Default keep-alive timeout — https://gunicorn.org/reference/settings/ (settings keepalive)

"Command line: --keep-alive INT" "Default: 2" "The number of seconds to wait for requests on a Keep-Alive connection." "sync worker does not support persistent connections and will ignore this option."

G5a. HTTP/2 support (guide) — https://gunicorn.org/guides/http2/

"HTTP/2 support is a beta feature introduced in Gunicorn 25.0.0." "HTTP/2 support requires: SSL/TLS: HTTP/2 uses ALPN (Application-Layer Protocol Negotiation) which requires an encrypted connection … h2 library: Install with pip install gunicorn[http2] or pip install h2 Compatible worker: gthread, gevent, or ASGI workers" "Enable HTTP/2 by setting the --http-protocols option: gunicorn myapp:app --http-protocols h2,h1"

G5b. HTTP/2 support (settings) — https://gunicorn.org/reference/settings/ (settings http_protocols)

"Command line: --http-protocols STRING" "Default: 'h1'" "Valid protocols: h1 - HTTP/1.1 (default) / h2 - HTTP/2 (TLS with ALPN, or cleartext via http2_cleartext)"

G5c. Cleartext HTTP/2 (h2c) — https://gunicorn.org/reference/settings/ (settings http2_cleartext)

"Command line: --http2-cleartext STRING" "Default: 'off'" "Accept HTTP/2 over cleartext TCP (h2c), and by which mechanism. Valid values are: off (default) … prior-knowledge … upgrade … both"

G6. HTTP/3 — not documented. The only protocols listed as valid for http_protocols on https://gunicorn.org/reference/settings/ are h1 and h2 (see G5b); no fetched Gunicorn page mentions HTTP/3.

G7. Graceful shutdown mechanism — https://gunicorn.org/signals/ (Master process)

"TERM — graceful shutdown; waits for workers to finish requests up to graceful_timeout."

G8. Graceful shutdown timeout setting and default — https://gunicorn.org/reference/settings/ (settings graceful_timeout)

"Command line: --graceful-timeout INT" "Default: 30" "After receiving a restart signal, workers have this much time to finish serving requests. Workers still alive after the timeout (starting from the receipt of the restart signal) are force killed."

Uvicorn

U1. Default bind host — https://uvicorn.dev/settings/ (Socket Binding)

"--host <str> - Bind socket to this host. Use --host 0.0.0.0 to make the application available on your local network. … Default: '127.0.0.1'."

U2. Default bind port — https://uvicorn.dev/settings/ (Socket Binding)

"--port <int> - Bind to a socket with this port. If set to 0, an available port will be picked. Default: 8000."

U3. Default number of workers — https://uvicorn.dev/settings/ (Production)

"--workers <int> - Number of worker processes. Defaults to the $WEB_CONCURRENCY environment variable if available, or 1. Not valid with --reload."

U4. Worker timeout / closest equivalent — https://uvicorn.dev/settings/ (Production)

"--timeout-worker-healthcheck <int> - Maximum number of seconds to wait for a worker to respond to a healthcheck. Default: 5."

Related behavior on stuck workers — https://uvicorn.dev/deployment/ (Built-in process manager):

"The default process manager monitors the status of child processes and automatically restarts child processes that die unexpectedly. Not only that, it will also monitor the status of the child process through the pipeline. When the child process is accidentally stuck, the corresponding child process will be killed through an unstoppable system signal or interface."

U5. Default keep-alive timeout — https://uvicorn.dev/settings/ (Timeouts)

"--timeout-keep-alive <int> - Close Keep-Alive connections if no new data is received within this timeout (in seconds). Default: 5."

Corroborated by https://uvicorn.dev/server-behavior/ (Timeouts):

"Keep-Alive. Defaults to 5 seconds. Between requests, connections must receive new data within this period or be disconnected."

U6a. HTTP/2 support (concept page) — https://uvicorn.dev/concepts/http2/

"Uvicorn has experimental support for HTTP/2, built on the zttp parser." "HTTP/2 support is currently experimental and is not enabled by default." "To enable it, select the zttp HTTP implementation and pass --http2: uvicorn main:app --http zttp --http2"

U6b. HTTP/2 flag and default — https://uvicorn.dev/settings/ (Implementation)

"--http2 - Enable HTTP/2. This requires --http zttp. Default: False."

Index page statement — https://uvicorn.dev/:

"Uvicorn currently supports HTTP/1.1, HTTP/2 and WebSockets."

U7. HTTP/3 — not documented. No fetched Uvicorn page mentions HTTP/3; the index page's protocol list (see U6b) covers only HTTP/1.1, HTTP/2 and WebSockets.

U8a. Graceful shutdown mechanism — https://uvicorn.dev/server-behavior/ (Graceful Process Shutdown)

"Uvicorn handles process shutdown gracefully, ensuring that connections are properly finalized, and all tasks have run to completion. During a shutdown period Uvicorn will ensure that responses and tasks must still complete within the configured timeout periods."

U8b. Graceful shutdown timeout setting — https://uvicorn.dev/settings/ (Timeouts)

"--timeout-graceful-shutdown <int> - Maximum number of seconds to wait for graceful shutdown. After this timeout, the server will start terminating requests."

Default value of --timeout-graceful-shutdown: not documented (no default is stated on the settings page or any other fetched Uvicorn page). The specific signal that triggers shutdown (e.g. SIGTERM) is also not stated on the fetched pages.

Ambiguous or contradictory items

  1. Gunicorn workers default vs. prose — on https://gunicorn.org/reference/settings/ the workers entry states "Default: 1", but the same entry's prose says the WEB_CONCURRENCY environment variable is used by default when set. Effective behavior is "WEB_CONCURRENCY, else 1", but the Default field and the prose are not worded consistently.
  2. Hypercorn default bind — the configuration options table (https://hypercorn.readthedocs.io/en/latest/how_to_guides/configuring.html) leaves the Default column blank for bind, while the Binds guide (https://hypercorn.readthedocs.io/en/latest/how_to_guides/binds.html) explicitly states the default is "127.0.0.1:8000". The two pages agree only via the guide.
  3. Uvicorn HTTP/2 status — the index page (https://uvicorn.dev/) says "Uvicorn currently supports HTTP/1.1, HTTP/2 and WebSockets" (reads as first-class support), while the HTTP/2 concept page (https://uvicorn.dev/concepts/http2/) calls it "experimental and is not enabled by default" and the settings page (https://uvicorn.dev/settings/) shows --http2 with Default: False.
  4. Hypercorn graceful_timeout entry is truncated — the description ends mid-sentence ("…for any remaining requests (tasks) to") and no default is given. It is also easy to confuse with shutdown_timeout (default 60 s), which only covers Lifespan shutdown completion — a different phase.
  5. Uvicorn --timeout-graceful-shutdown default is not documented — the flag and its behavior are documented on https://uvicorn.dev/settings/, but no default value appears on any fetched page (same for which signal triggers the shutdown).
  6. Gunicorn keep-alive default vs. default worker — keepalive defaults to 2 s, but the same settings page notes "sync worker does not support persistent connections and will ignore this option", and sync is the default worker_class. So the keep-alive default is effectively inert in a stock Gunicorn deployment.
  7. Documentation hosting — legacy Gunicorn doc URLs (docs.gunicorn.org/en/stable/…) return 404; the current official docs live at gunicorn.org. hypercorn.org was unreachable from this machine (transport errors), so the official Read the Docs build was used.
