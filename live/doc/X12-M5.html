  2. Default port — https://uvicorn.dev/settings/

  9. Graceful shutdown mechanism — https://uvicorn.dev/server-behavior/

    Uvicorn handles process shutdown gracefully, ensuring that connections are properly finalized, and all tasks have run to completion. During a shutdown period Uvicorn will ensure that responses and tasks must still complete within the configured timeout periods. Close any connections that are not currently waiting on an HTTP response, and wait for any other connections to finalize their HTTP responses.

Ambiguities and contradictions

  • Gunicorn docs version. docs.gunicorn.org/en/stable/settings.html now 404s (redirects to gunicorn.org/en/stable/settings.html). The current official site documents the latest release (entries marked "Added in 24.0.0", "Changed in 26.3.0"), so the HTTP/2 support (--http-protocols) and the HTTP/2 behavior notes under timeout/keepalive may not apply to older stable releases.
  • Gunicorn defaults are environment-dependent. The default bind becomes 0.0.0.0:$PORT when PORT is set, and the default worker count becomes $WEB_CONCURRENCY when set. Also, the default sync worker ignores keepalive entirely, so the documented 2 s keep-alive default has no effect with the default worker class.
  • Gunicorn graceful_timeout wording. The settings page describes graceful_timeout as the timeout for "graceful workers restart" after a "restart signal", while the signals page applies it to TERM shutdown ("waits for workers to finish requests up to graceful_timeout"); the two pages frame the same setting as restart vs. shutdown.
  • Uvicorn graceful-shutdown default. --timeout-graceful-shutdown has no documented default on the settings page (the code default is not stated in the docs fetched here), so its default is reported as "not documented".
  • Uvicorn worker timeout. Uvicorn documents no worker-kill timeout at all; --timeout-worker-healthcheck (5 s) is a healthcheck timeout, not a request timeout, and is offered only as the closest equivalent.
  • Uvicorn HTTP/2 is experimental and third-party. It is off by default and requires the separate zttp package (--http zttp --http2); the settings page and the HTTP/2 concepts page agree on this.
  • Hypercorn configuration table is incomplete. The bind and graceful_timeout rows have empty Default columns; the bind default is only stated on the separate Binds page, and the graceful_timeout description is truncated mid-sentence ("…for any remaining requests (tasks) to"), so its default value is nowhere documented on the fetched pages.
  • Hypercorn QUIC/HTTP-3. The --quic-bind option implies some QUIC plumbing exists, but no fetched page states whether HTTP/3 is actually supported; the docs' own search index contains no "HTTP3"/"HTTP/3" term.
  • Hypercorn has no worker timeout concept. Unlike Gunicorn's timeout, Hypercorn documents only socket-level timeouts (read_timeout default "No timeout.", plus shutdown_timeout/startup_timeout of 60 s for lifespan events), so the "worker timeout" row is reported as not documented.
