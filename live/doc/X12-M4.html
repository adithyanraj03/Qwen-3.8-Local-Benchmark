Ambiguities and contradictions

  1. Gunicorn bind default is environment-dependent. The settings page states Default: ['127.0.0.1:8000'] at the top of the bind entry, then says the default is ['0.0.0.0:$PORT'] when the PORT environment variable is defined. The headline default and the prose default disagree unless PORT is unset.
  2. Gunicorn workers default is also environment-dependent. The entry shows Default: 1 but also "By default, the value of the WEB_CONCURRENCY environment variable ... If it is not defined, the default is 1." Same pattern for Uvicorn ($WEB_CONCURRENCY first, then 1).
  3. Hypercorn graceful_timeout row is truncated in the docs. In both the rendered page and the raw .rst source, the purpose text ends mid-sentence ("...for any remaining requests (tasks) to") and the Default column is empty. The actual default graceful timeout cannot be derived from the documentation, so it is reported as "not documented".
  4. Hypercorn HTTP/3 is contradictory across pages. The index page advertises support for "HTTP/1, HTTP/2, WebSockets ... ASGI/2, and ASGI/3" without mentioning HTTP/3, yet the configuration table documents a UDP/QUIC bind (--quic-bind) and alt_svc_headers (Alt-Svc is the header used to advertise HTTP/3). No fetched page explicitly says "HTTP/3", so HTTP/3 support is reported as not explicitly documented.
  5. Uvicorn --timeout-graceful-shutdown has no documented default. The flag is described on the settings page but, unlike nearly every other option there, no "Default:" is given. The server-behavior page describes graceful shutdown without a number either.
  6. Gunicorn keep-alive default is worker-dependent. The documented default is 2 s, but the same entry notes the default sync worker "does not support persistent connections and will ignore this option", so the effective keep-alive behavior at defaults depends on the worker class.
  7. Gunicorn timeout and keepalive now also govern HTTP/2. Per the settings page ("Changed in 26.3.0"), timeout additionally bounds a stalled HTTP/2 stream and keepalive closes idle HTTP/2 connections; the HTTP/2 guide repeats this. This is consistent across the two pages but means the "worker timeout" and "keep-alive timeout" semantics differ between HTTP/1.1 and HTTP/2.
  8. Hypercorn has two shutdown-related timeouts. graceful_timeout (requests, default not documented) and shutdown_timeout (Lifespan shutdown, 60 s, no CLI flag). The docs do not describe how the two interact during a single SIGTERM shutdown.
  9. Gunicorn docs site migration. docs.gunicorn.org/en/stable/settings.html (the long-standing canonical URL) now returns 404; the current official docs live at gunicorn.org and describe newer behavior (native HTTP/2 added in 25.0.0, h2c in 26.2.0, HTTP/2 stream bounding in 26.3.0) that older cached copies of the docs do not contain.
