Gunicorn vs Uvicorn vs Hypercorn — defaults and behaviour

All values below were taken only from official documentation pages fetched in this session on 2026-11-14. No value comes from model memory. Where a page does not state a value, the cell says "not documented".

Documentation versions observed during the fetches:

  • Gunicorn: the current docs site (docs.gunicorn.org, MkDocs). The settings reference mentions features "Added in 25.0.0", "Added in 25.1.0" and "Changed in 26.3.0", i.e. it documents Gunicorn ≥ 26.3.
  • Uvicorn: the current docs site (uvicorn.dev).
  • Hypercorn: hypercorn.readthedocs.io "latest"; search results identify it as "Hypercorn 0.17.3 documentation".

Ambiguities and contradictions

  • Gunicorn keep-alive default 2 s vs the HTTP/2 guide's "keepalive = 120". The settings reference states keepalive Default: 2, while the HTTP/2 guide's "Recommended Settings" and "Recommended Security Settings" config samples both show keepalive = 120. These are recommendations, not defaults, but a reader skimming the guide could mistake 120 for the default. Also, the default sync worker ignores keepalive entirely, so the "default keep-alive timeout" only applies to non-default worker classes.
  • Gunicorn default bind is environment-dependent. The settings reference says the default becomes ['0.0.0.0:$PORT'] when the PORT environment variable is set, while the homepage advertises only http://127.0.0.1:8000. Both are on official pages; the homepage omits the PORT caveat.
  • Gunicorn timeout semantics vary by worker type. The same setting is described as killing silent workers, and the docs add: "For the non sync workers it just means that the worker process is still communicating and is not tied to the length of time required to handle a single request." Since 26.3.0 it also bounds stalled HTTP/2 streams. A single "worker timeout" number therefore means different things depending on worker class.
  • Uvicorn HTTP/2 stated as supported on the homepage but "experimental / not enabled by default" on the HTTP/2 page. The Welcome page says "Uvicorn currently supports HTTP/1.1, HTTP/2 and WebSockets" without the experimental caveat given at /concepts/http2/.
  • Uvicorn --timeout-graceful-shutdown has no documented default. The flag is documented but the page gives no Default: value, unlike every other timeout on the same page.
  • Uvicorn has no worker timeout at all. The closest documented mechanism is the worker healthcheck (--timeout-worker-healthcheck, default 5 s); the deployment page describes killing stuck workers without naming that setting, so the connection between the two is only implicit.
  • Hypercorn graceful_timeout is truncated in the docs themselves. In both the rendered table and the underlying RST source (_sources/how_to_guides/configuring.rst.txt), the row ends mid-sentence at "…for any remaining requests (tasks) to" and the Default column is empty. The full description and the default value are not documented on any fetched page (the API Reference page, which might document them, renders empty).
  • Hypercorn HTTP/3 is ambiguous. The configuration table offers --quic-bind ("The UDP/QUIC host/address to bind to") and alt_svc_headers, which imply QUIC capability, yet no documentation page states that HTTP/3 is supported and the index page's protocol list omits it. Reported as "not documented".
  • Hypercorn "worker timeout" has no analogue. Unlike Gunicorn (heartbeat-based timeout) or Uvicorn (healthcheck), Hypercorn's documented option list contains no worker liveness/timeout setting; the nearest documented timeouts are read_timeout (default "No timeout") and the 60 s lifespan/SSL-handshake timeouts, which have no command-line flags.
  • Gunicorn HTTP/3 config placeholder. The roadmap says the HTTP/3 protocol "is already reserved in the configuration and does nothing yet", i.e. configuration surface may exist for a feature that does nothing — consistent with, but distinct from, the settings reference, which never mentions HTTP/3.
