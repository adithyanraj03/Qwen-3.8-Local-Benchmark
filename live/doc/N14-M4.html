Architecture

Typer (v0.27.3, typer/__init__.py:3) is a CLI library that turns plain Python functions with type hints into command line applications. It is a declaration and conversion layer on top of a vendored copy of Click 8.3.1 (typer/_click/, see the header in typer/_click/__init__.py:1-3). All line references below are relative to the repository root.

Arrow direction is "imports". Notable edges:

  • typer/__init__.py (33 lines) is only re-exports: Typer, run, launch, Option, Argument, the typer.File* types, and a handful of Click conveniences (echo, prompt, style, ...) re-exported from typer/_click/.
  • typer/main.py (2022 lines) is the orchestrator. The Typer class (main.py:119), the decorators callback/command/add_typer (main.py:549, main.py:753, main.py:915), the whole function-signature to Click-parameter conversion (get_click_param main.py:1632, get_click_type main.py:1530), the pretty-exception hook (except_hook main.py:61), and run/launch (main.py:1902, main.py:1943).
  • typer/models.py (743 lines) holds the intermediate data objects that decorators record before anything is built: CommandInfo (models.py:200), TyperInfo (models.py:235), ParameterInfo/OptionInfo/ArgumentInfo (models.py:280, models.py:388, models.py:516), ParamMeta (models.py:620), the DefaultPlaceholder/Default machinery (models.py:170, models.py:190), the typer.File* marker types (models.py:41-158) and the TyperPath param type (models.py:648).
  • typer/params.py (1833 lines) is the user-facing Option() / Argument() factories: heavily overloaded signatures (params.py:16-77 and following) that just construct OptionInfo / ArgumentInfo from models.py.
  • typer/core.py (1221 lines) defines the Click subclasses that carry Typer behavior: TyperArgument (core.py:245), TyperOption (core.py:435), TyperCommand (core.py:903), TyperGroup (core.py:991), plus the adapted entry point _main (core.py:158) and the Rich feature flags HAS_RICH / DEFAULT_MARKUP_MODE (core.py:27-32).
  • typer/rich_utils.py (776 lines) renders help pages, errors and tracebacks with Rich (rich_format_help rich_utils.py:555, rich_format_error rich_utils.py:697). It is imported lazily inside functions (core.py:206-209, core.py:982, main.py:81-86) so that import typer never pays the Rich import cost when markup is disabled, and ruff enforces that no other module imports rich directly (pyproject.toml:200-205).
  • typer/utils.py contains the signature introspection: get_params_from_function (utils.py:107) plus the Annotated-aware splitting (utils.py:94-104) and its user-facing error classes.
  • typer/completion.py, typer/_completion_classes.py, typer/_completion_shared.py implement --install-completion / --show-completion and the per-shell completion scripts (bash/zsh/fish/ powershell, _completion_classes.py:28-222).
  • typer/testing.py is a self-contained CliRunner / Result (based on Click's runner) that invokes typer.main.get_command directly (testing.py:285) with stdin/stdout/stderr and os.environ swapped out (testing.py:158-273).
  • typer/cli.py is the typer console script itself (pyproject.toml:50-51): a Typer app (cli.py:17) with a custom TyperCLIGroup (cli.py:54) that dynamically injects a run command for any module (cli.py:140).
  • typer/exceptions.py defines Abort, Exit, TyperException. The vendored Click imports these (_click/core.py:19), so typer.exceptions is the single source of exit/abort control flow for both layers.
  • typer/_click/ is Click 8.3.1 copied and adapted: core.py (Context :118, Command :503, Parameter :805), parser.py (optparse-derived _OptionParser :207), types.py (ParamType hierarchy, convert_type :622), termui.py, formatting.py, shell_completion.py, exceptions.py, _compat.py, _winconsole.py. It depends on Typer only through typer.exceptions and TYPE_CHECKING-only imports of typer.core (_click/parser.py:36-38), keeping the dependency effectively acyclic.
  • typer/_typing.py (typing-introspection helpers copied from pydantic) and typer/_types.py (TyperChoice, _types.py:12, an enum/Literal-aware Choice) are leaf utilities.

Request flow: from a decorated function to a parsed command line

  1. Declaration is inert. @app.command() does not build anything; the decorator (main.py:753) appends a CommandInfo holding the raw function and settings to app.registered_commands (main.py:890-911). Same for @app.callback() (main.py:728-749) and app.add_typer() (main.py:1108-1131).

  2. Invocation triggers a build. app() (Typer.__call__, main.py:1133) installs except_hook and calls get_command(app) (main.py:1173). That decides between a TyperGroup (callback, sub-groups, or more than one command) and a bare single TyperCommand (main.py:1176-1205), and appends the completion options (main.py:1174-1175, built via completion.get_completion_inspect_parameters, completion.py:17).

  3. Function to parameters. get_command_from_info (main.py:1392) derives the command name (get_command_name, main.py:1360, lowercases and replaces _ with -), takes help from the docstring (main.py:1400-1404), and calls get_params_convertors_ctx_param_name_from_function (main.py:1373), which for each function parameter:

  • utils.get_params_from_function (utils.py:107) runs inspect.signature(..., eval_str=True) + get_type_hints, peels Annotated[T, Option()/Argument()] apart (utils.py:94-104), reconciles the "Annotated style" vs "default-value style" of declaring parameters (errors in utils.py:22-91), moves default_factory into default (utils.py:167-181) and returns ParamMeta(name, default, annotation) per parameter.
  • Parameters annotated as typer.Context are pulled out as the context injection point instead of becoming CLI parameters (main.py:1382-1384).
  • get_click_param (main.py:1632) classifies each ParamMeta: a ParameterInfo default or no default at all means Argument/required, a plain default means Option (main.py:1639-1652); it unwraps Optional[X], list[X] (becomes multiple/nargs=-1) and tuple[...] (main.py:1665-1693); get_click_type (main.py:1530) maps the annotation to a Click ParamType (str->STRING, int+min/max->IntRange, Path->TyperPath, Enum/Literal->TyperChoice, typer.File*->File, parser=->FuncParamType, click_type= passthrough); bool options become --flag/--no-flag pairs (main.py:1706-1719); user callbacks are adapted to Click's (ctx, param, value) shape by get_param_callback (main.py:1797) and autocompletion functions by get_param_completion (main.py:1849). The result is a TyperArgument/TyperOption (core.py:245, core.py:435) plus an optional post-conversion callable for Path/Enum values (determine_type_convertor, main.py:1437).

  1. Command assembly. A TyperCommand/TyperGroup (core.py:903, core.py:991) is instantiated with those params and a wrapped callback: get_callback (main.py:1496) returns a wrapper that applies the convertors, injects the live Context if the function declared one (main.py:1522-1523) and calls the user function with keyword arguments. Groups recurse through get_group_from_info (main.py:1283), resolving per-level settings with solve_typer_info_defaults (main.py:1248).

  2. Parsing. Typer.__call__ ends up in TyperCommand.main -> _main (core.py:158): reads sys.argv (with Windows glob expansion, core.py:173-174), short-circuits shell-completion env-var requests (core.py:182, core.py:882-900), then Command.make_context (_click/core.py:687) creates a Context and calls parse_args (_click/core.py:711). make_parser (_click/core.py:611) asks every parameter to register itself on the optparse-derived _OptionParser (_click/parser.py:207): TyperOption.add_to_parser (core.py:588) handles flags/secondary opts/multiple/count, TyperArgument.add_to_parser (core.py:431) handles positionals. parser.parse_args (_click/parser.py:275) returns (opts, remaining_args, invocation_order).

  3. Value processing. For each parameter, ordered eager-first and invocation-order-second (iter_params_for_processing, _click/core.py:74), Parameter.handle_parse_result (_click/core.py:1051) runs consume_value (command line -> env var -> default_map -> default, _click/core.py:920, with Typer's auto-envvar extension in TyperOption.resolve_envvar_value, core.py:686), then type_cast_value/process_value (_click/core.py:940, _click/core.py:988) which invoke the ParamType.convert (e.g. TyperChoice.convert, _types.py:71), enforce required, and run the parameter callback. Values land in ctx.params (_click/core.py:1077).

  4. Dispatch. TyperGroup.invoke (core.py:1088) resolves the subcommand name (resolve_command, core.py:1171, which adds "Did you mean" typo suggestions), invokes the group callback, then builds a child context for the chosen command and invokes it. Command.invoke (_click/core.py:729) finally calls ctx.invoke(self.callback, **ctx.params) -> the get_callback wrapper -> the user's function, with converted Python values.

  5. Error and exit handling lives in _main (core.py:184-242): ClickException is rendered as a Rich error panel (rich_utils.py:697) or plain text, typer.Exit/Abort/EOFError/KeyboardInterrupt map to exit codes, and user-code tracebacks are filtered by except_hook (main.py:61) which hides Typer/Click frames (optionally with Rich, main.py:81-87).

Design decisions

Good

  1. Lazy, two-phase construction. Decorators only record plain data objects (CommandInfo, TyperInfo, ParameterInfo); the Click object tree is rebuilt from scratch on every invocation in get_command (main.py:1173). This is what makes add_typer(name=..., help=...) overrides possible at any time, keeps Typer instances mutable after decoration, makes the app introspectable without executing anything (tests and typer/cli.py rely on this), and avoids stale state between runs. The cost is per-invocation rebuild, which is irrelevant for CLI startup.

  2. DefaultPlaceholder for "was this explicitly set?" (models.py:170-197). Because None/False are meaningful explicit values, Typer wraps every default in Typer.__init__/TyperInfo with Default(...) and resolves precedence in solve_typer_info_defaults (main.py:1248-1280): add_typer(...) > sub_app.callback(...) > Typer(...) > default, with a parallel six-step chain for help text (solve_typer_info_help, main.py:1211-1245). This gives predictable inheritance across nested apps without sentinel-value ambiguity.

  3. Extension by subclassing a vendored Click, with lazy Rich. Typer never monkey-patches an installed Click; it owns typer/_click/ and layers TyperOption/TyperArgument/TyperCommand/TyperGroup on top (core.py:245-1221), overriding exactly the seams it needs (main, format_help, get_help_record, add_to_parser). Vendoring also lets the parser layer import typer.exceptions directly (_click/core.py:19), so typer.Exit/Abort are the same control-flow objects end to end, and users can still drop down to Click classes via cls=. Rich stays optional and lazy (core.py:206-209, core.py:982-988), keeping import typer cheap.

Would change

  1. The ~40-kwarg parameter plumbing is duplicated everywhere. Adding one new option setting today means editing: ParameterInfo.__init__ (models.py:280-385), OptionInfo.__init__ (models.py:388-513), ArgumentInfo.__init__ (models.py:516-617) - three near-identical copy-paste blocks that only forward their arguments - the four @overload declarations each for Option and Argument in params.py (1833 lines for two functions), the forwarding in get_click_param (main.py:1725-1793), and the TyperOption/TyperArgument constructors (core.py:248-299, core.py:440-539). The same story applies to Typer.__init__ vs callback vs command vs add_typer in main.py (four copies of ~20 params, main.py:135-1131). I would collapse the *Info classes onto a shared dataclass-style base with field() defaults and pass structured config through, keeping only the public overloads hand-written for IDE experience. This is the single largest maintenance tax in the codebase.

  2. Copy-paste-and-modify overrides of vendored internals. Several Typer behaviors are whole-function forks of Click code with a few lines changed: TyperOption.get_help_record duplicates ~90 lines of Click logic "only to modify a single line" (core.py:752-845, the comment at core.py:753-755 says so), _main is a fork of Click's main (core.py:158-169), _typer_format_options (core.py:861) and even _split_opt exist twice (core.py:36 and _click/parser.py:102). Since _click/ is pinned to Click 8.3.1 (_click/__init__.py:2), every upstream fix must be ported by hand, and the forks silently drift from their originals. I would refactor these into small template-method hooks on the vendored classes (e.g. a write_extra_help_bits() hook instead of forking get_help_record) so future Click re-vendoring is a diff, not a re-audit.
