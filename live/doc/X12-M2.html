Gunicorn vs Uvicorn vs Hypercorn — defaults & configuration comparison

Every value below comes from an official documentation page fetched in this session (2026-10-24). No value is taken from memory. Where the official documentation does not state a value, the cell says Not documented.

Note on source locations: www.uvicorn.org and hypercorn.org no longer resolve (DNS failures observed this session). The current official documentation, as linked from the official project repositories, is:

  • Gunicorn: https://docs.gunicorn.org/ (official docs site, "benoitc/gunicorn")
  • Uvicorn: https://uvicorn.dev/ (official docs site, "Kludex/uvicorn"; the encode/uvicorn repo redirects to Kludex/uvicorn)
  • Hypercorn: https://hypercorn.readthedocs.io/en/latest/ (official docs, "pgjones/hypercorn") plus the README at https://github.com/pgjones/hypercorn

Citations

Every value in the table has its own citation below: the exact URL of the page fetched in this session, followed by a short verbatim quote from that page.

Gunicorn

  • [G1] Default bind 127.0.0.1:8000; flag -b/--bind. Page: https://docs.gunicorn.org/reference/settings/

    Command line: -b ADDRESS, --bind ADDRESS Default: ['127.0.0.1:8000'] If the PORT environment variable is defined, the default is ['0.0.0.0:$PORT']. Corroborated by the homepage (https://docs.gunicorn.org/): gunicorn myapp:app — # Listening at http://127.0.0.1:8000.

  • [G2] Default workers 1 (or $WEB_CONCURRENCY); flag -w/--workers. Page: https://docs.gunicorn.org/reference/settings/

    Command line: -w INT, --workers INT Default: 1 By default, the value of the WEB_CONCURRENCY environment variable, which is set by some Platform-as-a-Service providers such as Heroku. If it is not defined, the default is 1.

  • [G3] Worker timeout default 30 s; setting timeout; flag -t/--timeout. Page: https://docs.gunicorn.org/reference/settings/

    Command line: -t INT, --timeout INT Default: 30 Workers silent for more than this many seconds are killed and restarted.

  • [G4] Keep-alive timeout default 2 s; setting keepalive; flag --keep-alive. Page: https://docs.gunicorn.org/reference/settings/

    Command line: --keep-alive INT Default: 2 The number of seconds to wait for requests on a Keep-Alive connection.

  • [G5] HTTP/2: beta, --http-protocols, TLS/ALPN + h2 library + compatible workers; h2c via --http2-cleartext. Page: https://docs.gunicorn.org/guides/http2/

    HTTP/2 support is a beta feature introduced in Gunicorn 25.0.0. HTTP/2 support requires: SSL/TLS: HTTP/2 uses ALPN ... h2 library: Install with pip install gunicorn[http2] Compatible worker: gthread, gevent, or ASGI workers Page: https://docs.gunicorn.org/reference/settings/ Command line: --http-protocols STRING Default: 'h1' h2 - HTTP/2 (TLS with ALPN, or cleartext via http2_cleartext) Command line: --http2-cleartext STRING — Default: 'off' — Accept HTTP/2 over cleartext TCP (h2c)

  • [G6] HTTP/3: not documented. No HTTP/3 or QUIC setting or page was found on any Gunicorn docs page fetched (reference/settings/, guides/http2/, faq/, design/, signals/, run/, homepage). The only HTTP/3 occurrence is a passing remark in the HTTP/2 guide's RFC-compliance table (https://docs.gunicorn.org/guides/http2/): "Server Push (PUSH_PROMISE) is not implemented. This is an optional HTTP/2 feature that is being deprecated in HTTP/3".

  • [G7] Graceful shutdown via TERM (master and workers); QUIT/INT quick; HUP graceful reload. Page: https://docs.gunicorn.org/signals/

    TERM — graceful shutdown; waits for workers to finish requests up to graceful_timeout. (Worker process:) TERM — graceful shutdown. QUIT, INT — quick shutdown. HUP — reload configuration, spawn new workers, and gracefully stop old ones.

  • [G8] Shutdown-timeout setting graceful_timeout, default 30 s; flag --graceful-timeout. Page: https://docs.gunicorn.org/reference/settings/

    Command line: --graceful-timeout INT Default: 30 Timeout for graceful workers restart in seconds. After receiving a restart signal, workers have this much time to finish serving requests. Workers still alive after the timeout (starting from the receipt of the restart signal) are force killed.

Uvicorn

  • [U1] Default host 127.0.0.1 (--host), port 8000 (--port). Page: https://uvicorn.dev/settings/

    --host <str> - Bind socket to this host. ... Default: '127.0.0.1'. --port <int> - Bind to a socket with this port. If set to 0, an available port will be picked. Default: 8000.

  • [U2] Default workers 1 (or $WEB_CONCURRENCY); flag --workers. Page: https://uvicorn.dev/settings/

    --workers <int> - Number of worker processes. Defaults to the $WEB_CONCURRENCY environment variable if available, or 1. Not valid with --reload.

  • [U3] Worker timeout: closest documented equivalent is the health-check timeout, default 5 s; flag --timeout-worker-healthcheck. Page: https://uvicorn.dev/settings/

    --timeout-worker-healthcheck <int> - Maximum number of seconds to wait for a worker to respond to a healthcheck. Default: 5. The docs pages fetched (settings, server-behavior, deployment) do not document a general per-worker or per-request timeout for standalone uvicorn.

  • [U4] Keep-alive timeout default 5 s; flag --timeout-keep-alive. Page: https://uvicorn.dev/settings/

    --timeout-keep-alive <int> - Close Keep-Alive connections if no new data is received within this timeout (in seconds). Default: 5. Page: https://uvicorn.dev/server-behavior/ Keep-Alive. Defaults to 5 seconds. Between requests, connections must receive new data within this period or be disconnected.

  • [U5] HTTP/2: experimental, off by default, requires zttp parser; flags --http2 (+ --http zttp). Page: https://uvicorn.dev/settings/

    --http2 - Enable HTTP/2. This requires --http zttp. Default: False. Page: https://uvicorn.dev/concepts/http2/ Uvicorn has experimental support for HTTP/2, built on the zttp parser. HTTP/2 support is currently experimental and is not enabled by default. uvicorn main:app --http zttp --http2 When using HTTPS, HTTP/2 is negotiated via ALPN ... The HTTP/1.1 Upgrade: h2c mechanism is not supported Page: https://uvicorn.dev/concepts/http-protocols/ The zttp implementation serves HTTP/1.1 by default. This keeps experimental HTTP/2 support opt-in.

  • [U6] HTTP/3: not documented. No HTTP/3 or QUIC setting or page was found on any Uvicorn docs page fetched (settings, server-behavior, concepts/http2, concepts/http-protocols, deployment, index, release-notes).

  • [U7] Graceful shutdown: connections finalized and tasks run to completion within the configured timeout; SIGHUP = graceful restart. Page: https://uvicorn.dev/server-behavior/

    Uvicorn handles process shutdown gracefully, ensuring that connections are properly finalized, and all tasks have run to completion. During a shutdown period Uvicorn will ensure that responses and tasks must still complete within the configured timeout periods. Page: https://uvicorn.dev/deployment/ SIGHUP: Gracefully restart the workers one at a time with no dropped requests.

  • [U8] Shutdown-timeout setting timeout_graceful_shutdown, default not documented; flag --timeout-graceful-shutdown. Page: https://uvicorn.dev/settings/

    --timeout-graceful-shutdown <int> - Maximum number of seconds to wait for graceful shutdown. After this timeout, the server will start terminating requests. (No default value is stated on this page or on the server-behavior/deployment pages fetched. The release notes confirm the option's existence without a default: https://uvicorn.dev/release-notes/ — "Add --timeout-graceful-shutdown parameter (#1950)", listed under 0.22.0 (April 28, 2023).)

Hypercorn

  • [H1] Default bind 127.0.0.1:8000; flag -b/--bind. Page: https://hypercorn.readthedocs.io/en/latest/how_to_guides/binds.html

    By default Hypercorn will bind to “127.0.0.1:8000”. Corroborated by the quickstart (https://hypercorn.readthedocs.io/en/latest/tutorials/quickstart.html): hypercorn hello_world:app then curl localhost:8000. Flag: https://hypercorn.readthedocs.io/en/latest/how_to_guides/configuring.html bind | -b, --bind | The TCP host/address to bind to. Should be either host:port, host, unix:path or fd://num

  • [H2] Default workers 1; flag -w/--workers. Page: https://hypercorn.readthedocs.io/en/latest/how_to_guides/configuring.html

    workers | -w, --workers | The number of workers to spawn and use. | 1

  • [H3] Worker timeout: no worker-liveness timeout documented; closest is read_timeout = "No timeout."; flag --read-timeout. Page: https://hypercorn.readthedocs.io/en/latest/how_to_guides/configuring.html

    read_timeout | --read-timeout | Seconds to wait before timing out reads on TCP sockets. | No timeout. No worker-timeout/heartbeat setting appears in the configuration reference table fetched.

  • [H4] Keep-alive timeout default 5s; flag --keep-alive. Page: https://hypercorn.readthedocs.io/en/latest/how_to_guides/configuring.html

    keep_alive_timeout | --keep-alive | Seconds to keep inactive connections alive before closing. | 5s

  • [H5] HTTP/2: supported by default over TLS (ALPN h2 + http/1.1); h2c upgrade supported; no dedicated enable flag documented. Page: https://hypercorn.readthedocs.io/en/latest/discussion/http2.html

    Hypercorn is based on the excellent hyper-h2 library. By default Hypercorn will set h2 and http/1.1 as the ALPN protocols. Hypercorn, however, supports the h2c HTTP/1.1 to HTTP/2 upgrade process. This allows a client to send a HTTP/1.1 request with a Upgrade: h2c header that results in the connection being upgraded to HTTP/2. Page: https://hypercorn.readthedocs.io/en/latest/how_to_guides/configuring.html alpn_protocols | N/A | The HTTP protocols to advertise over ALPN. | h2 and http/1.1

  • [H6] HTTP/3: optional, via aioquic, hypercorn[h3] extra + --quic-bind. Page: https://github.com/pgjones/hypercorn (official repository README)

    Hypercorn can optionally serve the current draft of the HTTP/3 specification using the aioquic library. To enable this install the h3 optional extra, pip install hypercorn[h3] and then choose a quic binding e.g. hypercorn --quic-bind localhost:4433 .... Page: https://hypercorn.readthedocs.io/en/latest/how_to_guides/configuring.html quic_bind | --quic-bind | The UDP/QUIC host/address to bind to. See bind for formatting options.

  • [H7] Graceful shutdown: waits after SIGTERM or Ctrl-C for remaining requests/tasks; lifespan shutdown bounded separately by shutdown_timeout (60s, no CLI flag). Page: https://hypercorn.readthedocs.io/en/latest/how_to_guides/configuring.html

    graceful_timeout | --graceful-timeout | Time to wait after SIGTERM or Ctrl-C for any remaining requests (tasks) to shutdown_timeout | N/A | Timeout when waiting for Lifespan shutdowns to complete. | 60s (The graceful_timeout purpose sentence is truncated in the page source itself — see Ambiguities.)

  • [H8] Shutdown-timeout setting graceful_timeout, default not documented; flag --graceful-timeout. Page: https://hypercorn.readthedocs.io/en/latest/how_to_guides/configuring.html (and its raw source https://hypercorn.readthedocs.io/en/latest/_sources/how_to_guides/configuring.rst.txt)

    graceful_timeout | --graceful-timeout | Time to wait after SIGTERM or Ctrl-C for any remaining requests (tasks) to The "Default" column for this row is empty in both the rendered page and the RST source; the API reference page (https://hypercorn.readthedocs.io/en/latest/reference/api.html) contains no per-setting defaults, so the default value is Not documented in the pages fetched.

Ambiguous or contradictory items

  1. Hypercorn graceful_timeout description is truncated and has no default. In both the rendered page and the raw RST source, the purpose text ends mid-sentence ("Time to wait after SIGTERM or Ctrl-C for any remaining requests (tasks) to") and the Default column is blank. So both the exact behavior and the default value are not documented.
  2. Hypercorn default bind is split across pages. The configuration reference table leaves the bind default blank; the default (127.0.0.1:8000) is only stated on the separate "Binds" how-to page.
  3. Uvicorn's official docs vs its README disagree in tone about HTTP/2. The README (https://github.com/encode/uvicorn) states "Uvicorn currently supports HTTP/1.1, HTTP/2 and WebSockets." (listing HTTP/2 unconditionally), while the docs site (https://uvicorn.dev/concepts/http2/) states HTTP/2 is "experimental" and "not enabled by default" and only available via the experimental zttp parser (--http zttp --http2), and the HTTP-protocols page adds "zttp support is currently experimental and not suited for production usage."
  4. Uvicorn's graceful-shutdown signal is not named. The Server Behavior page describes graceful shutdown behavior and the Settings page defines --timeout-graceful-shutdown, but the pages fetched do not state which signal (e.g. SIGTERM) triggers standalone uvicorn's graceful shutdown; only SIGHUP (graceful restart) and SIGTTIN/SIGTTOU (worker count) are documented, with a note that signal management is "Not supported on Windows".
  5. Uvicorn has no documented default for --timeout-graceful-shutdown. The setting is described without a default value, unlike every other setting on that page.
  6. Gunicorn's timeout serves a second role under HTTP/2. The settings page notes that on HTTP/2 connections the same timeout value "also bounds a single stream: a request body that makes no progress for this long ... is cancelled with RST_STREAM", so one setting controls both worker liveness and HTTP/2 stream progress.
  7. Gunicorn's default bind is conditional. It is 127.0.0.1:8000 unless the PORT environment variable is defined, in which case the default is 0.0.0.0:$PORT — so "the default" depends on the environment.
  8. Gunicorn keep-alive is worker-class dependent. The keepalive setting exists with a default of 2 seconds, but the design page says the default sync worker has "No keep-alive support (connections close after response)", and the FAQ explains this: "The default sync workers target Nginx, which uses HTTP/1.0 for upstream connections." So the effective default keep-alive behavior depends on worker_class.
  9. "Workers" means different things in Hypercorn's docs. -w/--workers sets the number of processes (default 1), while the "Workers" discussion page is about the event-loop worker class (worker_class, -k: asyncio/uvloop/trio) — the same word, two different settings.
  10. Hypercorn HTTP/3 information is not in the readthedocs docs proper. The readthedocs site has no HTTP/3 page; HTTP/3 support is documented in the official repo README (optional, "current draft of the HTTP/3 specification") and only indirectly in the docs via the quic_bind/--quic-bind configuration option.
  11. Gunicorn's settings reference is auto-generated and version-sensitive. The page is marked "Generated file — update gunicorn/config.py instead" and includes recent additions (HTTP/2 "Added in 25.0.0", http2_cleartext "Added in 26.2.0", dirty arbiters, control socket), so the defaults reflect the current docs build rather than any historical release; HTTP/2 itself is explicitly a "beta feature".
  12. Uvicorn process model differs, affecting "worker" semantics. The deployment page notes "Unlike gunicorn, uvicorn does not use pre-fork, but uses spawn", and uvicorn's multiprocess manager "monitors the status of the child process through the pipeline. When the child process is accidentally stuck, the corresponding child process will be killed" — this pipeline-based stickiness detection is not documented as a tunable timeout, unlike gunicorn's timeout or uvicorn's --timeout-worker-healthcheck.
