Gunicorn vs Uvicorn vs Hypercorn - documented defaults

All values below were taken from the official documentation pages fetched on 2026-10-24 in this session. No value comes from prior knowledge. Where the fetched documentation does not state a value, the cell says not documented.

Pages used (fetched with curl, full HTML archived locally before quoting):

  • Gunicorn: https://gunicorn.org/reference/settings/, https://gunicorn.org/signals/, https://gunicorn.org/roadmap/, https://gunicorn.org/guides/http2/
  • Uvicorn: https://uvicorn.dev/settings/, https://uvicorn.dev/server-behavior/, https://uvicorn.dev/concepts/http2/, https://uvicorn.dev/deployment/
  • Hypercorn: https://hypercorn.readthedocs.io/en/latest/how_to_guides/configuring.html, https://hypercorn.readthedocs.io/en/latest/how_to_guides/binds.html, https://hypercorn.readthedocs.io/en/latest/discussion/http2.html

Note: the Gunicorn settings reference describes the current release line (it contains entries "Added in 25.0.0", "Added in 26.2.0", "Changed in 26.3.0"). The Uvicorn site describes a current version that includes the experimental zttp/zuvloop implementations. The Hypercorn pages are the latest build on Read the Docs.

Gunicorn

Default bind address and port - https://gunicorn.org/reference/settings/

Default: ['127.0.0.1:8000']

If the PORT environment variable is defined, the default is ['0.0.0.0:$PORT']. If it is not defined, the default is ['127.0.0.1:8000'].

Bind CLI flag - https://gunicorn.org/reference/settings/

Command line: -b ADDRESS, --bind ADDRESS

Default number of workers - https://gunicorn.org/reference/settings/

workers ... Default: 1 ... The number of worker processes for handling requests.

By default, the value of the WEB_CONCURRENCY environment variable, which is set by some Platform-as-a-Service providers such as Heroku. If it is not defined, the default is 1.

Workers CLI flag - https://gunicorn.org/reference/settings/

Command line: -w INT, --workers INT

timeout ... Command line: -t INT, --timeout INT ... Default: 30

Workers silent for more than this many seconds are killed and restarted.

Worker timeout CLI flag - https://gunicorn.org/reference/settings/

Command line: -t INT, --timeout INT

keepalive ... Command line: --keep-alive INT ... Default: 2

The number of seconds to wait for requests on a Keep-Alive connection.

sync worker does not support persistent connections and will ignore this option.

Command line: --keep-alive INT

Ambiguities and contradictions

  1. Gunicorn's default bind is conditional. The same reference entry states the default as ['127.0.0.1:8000'] and also "If the PORT environment variable is defined, the default is ['0.0.0.0:$PORT']". The effective default therefore depends on the environment.
  2. Gunicorn's default worker count is likewise conditional on WEB_CONCURRENCY; 1 applies only when that variable is unset. Uvicorn documents the same WEB_CONCURRENCY fallback for --workers.
  3. Gunicorn's docs moved. https://docs.gunicorn.org/en/stable/settings.html now 301-redirects to https://gunicorn.org/en/stable/settings.html, which returns 404; the live reference is https://gunicorn.org/reference/settings/. Older third-party material (and the old docs domain) predates native HTTP/2, which the current reference documents as "Added in 25.0.0".
  4. Gunicorn HTTP/2 maturity is described inconsistently: the settings reference documents http_protocols/--http-protocols as a normal setting, while the roadmap says HTTP/2 shipped "as beta" and lists "Taking what shipped as beta toward something dependable" as current work. The settings page itself does not label it beta.
  5. Gunicorn's keepalive default of 2 s is documented as ignored by the default sync worker, so the documented default has no effect under the default worker class.
  6. Uvicorn's --timeout-graceful-shutdown entry is the only timeout on the settings page with no "Default:" stated; the default value is therefore not documented (the code default is not quoted anywhere on the pages fetched).
  7. Uvicorn's HTTP/2 story is recent and implementation-specific: the settings page says --http2 "requires --http zttp", and zttp is described as "experimental" and needing a separate package (pip install zttp). Older Uvicorn documentation did not describe HTTP/2 this way, so quotes from this site are version-sensitive.
  8. Hypercorn's graceful_timeout table row is truncated mid-sentence in the published page ("...for any remaining requests (tasks) to") and its Default column is empty, so neither the full behavior nor the default timeout is documented.
  9. Hypercorn's bind default is stated on the binds page ("127.0.0.1:8000") but the Default column of the bind row in the configuration-options table is empty - a minor inconsistency between two official pages.
  10. Hypercorn's HTTP/3 status is unclear: --quic-bind implies QUIC capability, but no fetched page says "HTTP/3", states whether it is enabled by default, or gives a default for quic_bind.
  11. "Worker timeout" has no exact Uvicorn or Hypercorn equivalent. Uvicorn's --timeout-worker-healthcheck (default 5) bounds how long a worker may fail to answer the multiprocess manager's healthcheck, not how long a request may run, so it is reported as the closest equivalent rather than a true worker timeout. Hypercorn's only comparable documented knob is read_timeout (default "No timeout"), which bounds socket reads, not worker liveness. The table entries for those two servers are therefore interpretations, flagged as such.
  12. Hypercorn has two shutdown-related timeouts (graceful_timeout for remaining request tasks, shutdown_timeout = 60s for Lifespan shutdown); only the former has a CLI flag. The docs do not describe how the two interact.
