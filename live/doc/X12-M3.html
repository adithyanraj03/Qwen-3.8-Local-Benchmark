Ambiguities / contradictions

  • Hypercorn's default bind: the configuration options table leaves the bind default cell empty, while the Binds guide states "By default Hypercorn will bind to "127.0.0.1:8000"". Not contradictory, but the value is documented on only one page.
  • Hypercorn's graceful_timeout description is truncated in the options table ("…for any remaining requests (tasks) to"), and no default value is given anywhere in the fetched pages. Note the table also lists a separate shutdown_timeout (default 60 s) that is described as "Timeout when waiting for Lifespan shutdowns to complete" with no CLI flag — it is a different mechanism, not the graceful-request timeout.
  • Gunicorn's graceful_timeout documentation speaks of "a restart signal" (HUP), while in practice it also bounds SIGTERM shutdown; the fetched settings page does not explicitly say "shutdown".
  • Uvicorn's --timeout-graceful-shutdown has no documented default on the fetched page (it says what happens after the timeout, not what the default is).
  • Uvicorn's worker timeout: there is no Gunicorn-style "silent worker" timeout at all; the only worker-related timeout documented is --timeout-worker-healthcheck (5 s), which measures something different (healthcheck response, not request silence).
  • HTTP/3 status differs in kind, not just in value: Gunicorn and Uvicorn simply have no HTTP/3 section in their fetched docs, whereas Hypercorn documents a --quic-bind option but no page explaining HTTP/3 behavior, so "supported" vs "not documented" is not cleanly distinguishable from the readthedocs pages alone.
  • Gunicorn HTTP/2 maturity: the settings reference documents --http-protocols as a normal setting, but the HTTP/2 guide labels the feature "beta … introduced in Gunicorn 25.0.0" — treat it as newer/less battle-tested than the core HTTP/1 path.
  • Uvicorn HTTP/2 backend: the current docs tie HTTP/2 exclusively to the zttp parser ("This requires --http zttp"), with zttp itself labeled "experimental and not suited for production usage" on the HTTP Protocols page.
